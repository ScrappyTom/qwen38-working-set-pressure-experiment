# Development method for the host-model coding loop

The goal is correct, checked contributions that survive changing evidence at a
reasonable total cost. Exact custody and valid tool actions support that goal;
they do not substitute for it.

Use the current decision register in
development/workload_requalification/contribution_cycle/PLAN.md. Keep a short
list of unresolved operating questions. Alternative implementations are candidate
answers, not automatically separate programmes of work.

For each tranche:

1. State one question, the observed failure or opportunity, the proposed mechanism,
   what remains fixed, and what each outcome would justify. Bind actual artifacts.
2. Qualify preservation and transitions on CPU, including plausible inefficient
   choices and rejection. Then inspect the actual information path: what in the
   input supports the next scripted decision, and what did the researcher supply?
3. Qualify the actual wire, template and decoder before exposure. Run a bounded
   coding contribution with declared cost controls and no live coaching. Review
   its actual inputs, full outputs, operations, observations and artifacts.
4. Decide: retain, repair a demonstrated defect, test a specific policy, or stop
   the approach. A report does not automatically earn another annotation or run.
5. Transfer useful policies to fresh coding work. Saved-state diagnostics and
   fresh autonomous work have different claims. Borrow relevant sister-project
   fixtures without reopening the separate reading-comprehension programme.

The operator must declare opportunity and cost separately. Request counts do not
bound half-hour responses. A spending stop is an apparatus outcome, not a failed
task check, and never authorizes executing an unfinished private draft. Account,
source-selection or objective changes must not silently restart a cost allowance.

Measure correctness, regressions, artifact preservation, actual feedback use,
termination, input/generation, elapsed time, and review effort. If reviewer time
was not measured, record it as unknown. Shorter reasoning and more account updates
are not success criteria on their own. Full scripted completion proves a feasible
host route, not that the model would select or finish it.

Consult Qwen between runs when a concrete unresolved design question warrants it.
Owner-imposed GPU stops take precedence; a consultation is not an automatic
prerequisite for implementing already-authorized mechanical or policy work.
Every live run must use its declared policy. Retrospective findings remain outside
the actor's input unless a separately identified review-directed job is prepared.

Prefer the existing store, selection, account, proposal and check machinery.
General scaffolding uses current versions, actual observations, explicit model
choices and declared limits. Task-specific semantic answers remain the model's
responsibility. Checkers and reference routes remain identified research support.
