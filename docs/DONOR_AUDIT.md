# Donor and prior-work audit

Date: 2026-08-28

## Decision

Do not build another context controller from scratch.

The owner's GitHub account already contains a connected experimental lineage
covering exact receipt demotion, recurrent pressure handling, chronology-free
state recomposition, exact workspace directories, focus relocation,
model-managed residency, semantic digests, bounded notes/frontiers, and a
model-authored progress state. Direct result and transcript audits show that
most of these mechanisms are mechanically viable but do not solve the present
evidence-to-action failure.

The next study should therefore reuse the current repository's qualified P0,
progress-pointer, exact-custody, observation-reopen, live-runtime, and replay
paths. It should change only reasoning mode on fresh sibling cases. No prior
mechanism below is promoted merely because code exists.

## Audit method

The audit inspected repository identities plus the actual `README.md`,
`RESULTS.md`, and, where relevant, `DIRECT_TRANSCRIPT_AUDIT.md` records. It did
not infer utility from repository names or mechanical receipts alone.

GitHub default-branch tips were resolved on 2026-08-28. The pinned tips below
are evidence identities for design selection; any copied source must receive a
file-level hash receipt at import time.

## Context-pressure lineage

### Exact receipt substitution

Repositories:

- `qwen38-context-reduction-pressure-boundary-v0`
  at `ab0e21b201d04521a43f83c223a364bca35a7b86`
- `qwen38-recurrent-context-reduction-v0`
  at `9a42b85b4d9fd25bd873d45c08a403c2ca1ff96e`
- `qwen38-recurrent-context-reduction-horizon-v0`
  at `f52642ec85efdc8f7196515503a0312af7c38d78`

Result: deterministic oldest-first exact-backed receipt substitution restored
capacity at authentic result-delivery boundaries and operated recurrently.
Longer continuations remained entirely acquisition/reopen behavior: 24/24
decisions in the horizon study were acquisitions, with no mutation or
submission. One trajectory entered repeated exact reopen cycles.

Decision: retain as a proven capacity mechanism and potential future donor for
receipt creation, token-savings calculation, and pressure-trigger handling.
Do not treat it as a working-state or action-control solution, and do not add it
to the next reasoning diagnostic.

### Chronology-free recurrent exact state

Repository: `qwen38-recurrent-exact-state-recomposition-v0`
at `c22cff99a0a1111215940c478db50e5762f1c5d3`.

Result: both observation and effect updates crossed recurrent reconstruction
boundaries, but nine direct-audited calls produced no new mutation or
submission. The observation case repeated the same target opening three times
and requested resident R033 twice. The effect case requested resident exact
candidate content until even fresh recomposition could no longer absorb the
duplicate result.

Reusable source candidates include `apparatus/packet.py`, `runner.py`,
`environment.py`, `modelio.py`, `replay.py`, and `seal.py`. These are donors,
not wholesale dependencies; the current project already has smaller qualified
equivalents for most of them.

Decision: use as a reference for exact replacement-state invariants and replay,
not as the next treatment. Exact availability alone already failed to produce
stable action.

### Pressure-qualified lifecycle runner

Repository: `qwen38-pressure-qualified-lifecycle-scout-v1`
at `e4dcd58fa554e7e36b99e6cb454803cd099d2044`.

Result: the system repeatedly resolved pressure and recovered 80,497
cumulative prompt tokens in each completed 18-call trajectory, but the two
seeds reproduced the same all-acquisition trajectory exactly. Neither mutated,
checked, nor submitted.

Decision: consult its launch, pressure-event, authorization, and lifecycle
custody code if recurrent pressure is reintroduced. Do not copy its large
phase apparatus into this minimal diagnostic.

## Representation and control-state lineage

### Model-authored bounded progress state

Repository: `qwen38-bounded-progress-state-utility-v0`
at `a3422cca49cb882ec252ba84903b856ba3cafc24`.

Direct result: a 169-token maintenance-authored state in a 464-token bound
package changed a byte-identical actor continuation from a redundant resident
read to immediate `submit`. Exact candidate-hash reconciliation later showed
the candidate was only `strong_partial`, with two partial requirement groups.
The intervention was therefore behaviorally salient but induced premature
closure. It also cost an 18,915-token maintenance call and bundled prose,
bindings, user-role recency, and authority wording.

Decision: do not rebuild or promote a generic progress-note controller. The
present Experiment 003 verbatim owner-authored pointer is smaller, cheaper, and
causally cleaner. If an action-state treatment is later earned, it must test
readiness discrimination and cannot simply cue closure.

### Bounded freeform notes and structured frontiers

Repositories:

- `qwen38-bounded-freeform-note-v0`
- `qwen38-bounded-note-expression-qualification-v0`
- `qwen38-bounded-frontier-expression-qualification-v0`
- `qwen38-closed-frontier-expression-qualification-v0`
  at `cde5d344f81ae3af6bc5e4c3838454b7b9a0d758`

Result: freeform maintenance often exhausted its completion budget. Structure
made two outputs mechanically bounded but cut six prose fields mid-thought and
truncated an exact handle. The closure-safe successor returned 0/2 complete
qualified objects. No actor-utility benefit was established.

Decision: do not spend another study on schema tuning or bounded semantic-note
expression. This branch is already closed for the current actor/runtime.

### Workspace directory and exact focus placement

Repositories:

- `qwen38-exact-workspace-directory-v0`
  at `801c1bf3d9daa8739629df86bf260d4ad08e3311`
- `qwen38-exact-focus-relocation-v0`
  at `1fc4bccadab37de5ab051e60248df6ed3353b4b3`
- `qwen38-accumulated-exact-focus-v0`
  at `6bed7b208174646b803405fdce1a83a9432fba88`

Direct result: an explicit exact directory did not prevent resident-content
rereads. Relocating one selected exact span made the duplicate result fit but
shifted both actors to complementary resident spans. Accumulating two recent
focus spans still produced one new acquisition and one exact reread, with no
mutation or submission.

Decision: do not rebuild directory or placement-only focus variants. They
address physical visibility, while Experiment 003 already shows the governing
fact can be present and correctly reacquired without conversion to action.

### Model-managed residency

Repository: `qwen38-dedicated-workspace-maintenance-v0`
at `44bade979d0ba1f1a2df3f2c919146c29d4c6868`.

Direct result: both maintenance outputs were syntactically valid and created
large headroom, but each released far more than necessary and each actor
immediately requested a source its manager had just released.

Decision: do not reintroduce KEEP/RELEASE planning or a dedicated residency
manager. Model management reachability was established; selection quality was
negative.

### Source-bound semantic digests

Repository: `qwen38-lossy-source-digest-utility-v0`
at `0081896cd5914acb14a155eb41342ffd3e788957`.

Direct result: a 218-token digest redirected the first read to a paired audit,
then the actor reopened the original exact source on the next call. It added a
720-token resident increment plus a 7,121-token production cost, avoided no raw
recovery, and produced no mutation.

Decision: do not rebuild semantic digestion before exact reacquisition has
shown a repeatable economic failure that a digest could prospectively repay.

## Generic exact-world substrate

Repository: `ScrappyTom/exact-world-agent-substrate`
at `d4933e93e0b19cf0756245c2451f1ed495f2b9a8`.

This is the strongest generic implementation donor. It provides exact purpose,
world, observation, request, effect, capability, delivery, history, replay,
cursor, event-chain, fsync, and recovery mechanics behind a closed high-level
API. It deliberately includes no live transport, GPU path, retry, or semantic
context policy.

Decision: preserve it as the preferred donor if this project later needs a
general reusable substrate. Do not replace the present qualified experiment
runner with it before the narrow reasoning diagnostic; that migration would be
larger than the earned change and would confound the comparison.

## Import policy for the next study

The next diagnostic imports no behavioral treatment from the older projects.
It reuses the already-qualified current repository and changes only the actor's
reasoning envelope.

Allowed future selective imports, only if subsequently earned:

- deterministic exact-backed receipt substitution;
- exact replacement-state packet invariants;
- recurrent pressure-event accounting;
- generic exact event/capability custody.

Rejected for the next study:

- semantic notes or digests;
- generic progress-state generation;
- workspace directories or focus relocation;
- model-selected residency;
- relationship graphs or opaque metadata IDs;
- host-selected relevance, readiness, or next action.
