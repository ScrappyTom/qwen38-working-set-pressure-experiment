# Host-path audit

The frozen host accurately executes and stores the selected operations. Its
working view eventually cannot deliver the next result under the selected
allowance. These are different findings.

`scripts/configparser_work.py` constructs each actual task/candidate/event view,
adds the retained complete reference and episode annotation, and removes the
previously retired resource illustration. Oldest-prefix externalization is
monotone. Ordered action/result signal remains resident; exact bodies leave the
prompt and retain their recovery handles. Private thinking is omitted immediately
from every subsequent input, without being bundled into result retrieval.

`scripts/run_configparser_backport.py` freezes the initial input, checks source
and runtime identities, preserves raw responses before interpretation, validates
the final action and applies exactly one operation. `VERIFICATION.json` confirms
32 raw/extracted responses, 32 exact tool/state replays and all 65 attempted
native inputs. Every sent continuation contains its newest complete result.
No rejected tool action or malformed final action occurs.

## Patch semantics and the damaging accepted edit

The supplied schema caps `old` and `new` at 512 decoded characters. Candidate
patching additionally enforces current candidate/file guards, unique exact
replacement and independent byte/diff/file bounds. These controls protect
identity and transport, not semantic preservation of text a replacement deletes.
The complete visible reference states the constraint; this is no longer the
earlier missing-signature problem.

C11's proposed `new` in thinking is 540 characters. Its final `new` is exactly
512 and loses `_UNSET` after a 508-character common prefix. The endpoint returns
that complete final; the host applies it exactly, with a matching successor diff.
There is no host truncation to repair. C12 recognizes the missing definition and
C13 restores it. `PATCH_BOUNDARY_PROBE.json` shows successful compilation but
failed module execution between those edits. A syntax-only preflight would not
have prevented the defect. The cap/final relationship earns investigation,
not an unproved assertion about the decoder's causal mechanism.

## Return construction, recovery and delivery

`ToolExecutor._read` selects the largest whole-line prefix meeting the 18,000-byte
source-body bound, 22,000-byte serialized result bound and exact-recovery wrapper
bound. It validates the complete result before committing coverage. `_bounded`
checks both original and future historical wrapper size. Mutation likewise
validates its complete successor result before committing the new candidate.
The earlier return-consistency repairs remain in force.

All 32 actual results and four actual patch payloads reopen exactly in the
separate offline `RECOVERY_PROBE.json`. The maximum wrapper is 21,229 bytes,
below 22,000, and the candidate remains unchanged. The original store/create
path is covered by exact replay; this probe exercises the saved wrapper path.
These are engineering checks, not Qwen-selected retrieval or proof of input
delivery. Qwen uses no `reopen_*` operation in this run.

Live `read_coverage` remains path-based historical acquisition, not proof that
the successor's changed content was inspected. The visible reference expressly
states that distinction. A page's `complete=true` means its returned range
reached EOF, not whole-file coverage. In particular C31 displays only the
documentation tail, and C32 was constructed but never delivered afterward.
No current-version inspection or semantic completion claim is derived from
those bookkeeping sets.

The selected read grammar contains no `line_count` or end-line argument. A
short exception inspection can return hundreds of lines; its new page may
displace the evidence needed for the next local contribution. The existing
codebase has a separately selected count-based read mode, but it was not this
actor's interface. Any use of that mode is an explicit intervention requiring
its own truthful reference and admission qualification.

## The terminal boundary

After C32, the host constructs C33 alternatives at prefixes 25–32. Their native
input counts are 28,618; 28,590; 24,385; 24,359; 24,275; 24,074; 23,928; 18,941.
The first fitting alternative removes the newest result. `latest_result_delivered`
then rejects it, so C33 is never sent. At prefix 31 the latest read alone adds
4,987 tokens to the all-bodies-external 18,941-token view. It exceeds the input
ceiling by 120, leaving only 32,648 physical generation tokens rather than the
reserved 32,768.

The full 17,988-byte read of test lines 467–885 still exists in exact storage.
The terminal gate protects against asking Qwen to act as though it received
that result. It does not provide a smaller usable result or solve accumulating
resident signal. Raising the ceiling by 120 on the consumed trajectory would
change the experiment and leave continuing history growth unresolved.

The passing source checks are bound to the actual final candidate; tests/docs
remain absent. C30's failed overall check leaves ten numerical actions, but
later capacity removes the opportunity to use all ten. Admission, acceptance,
delivery, checking and completed work remain separately reported.
