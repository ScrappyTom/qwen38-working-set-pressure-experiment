# Decision interface repair plan

Publish this plan before implementation. Implement an opt-in successor to
OperableSession; preserve historical evidence/configurations. The owner authorizes
engineering fixes and their qualification, not reopening consumed Qwen allowances.
No completion request, live coaching or model evaluation is included in this package.
Native rendering/tokenization and decoder qualification are engineering checks.

## Repairs and acceptance evidence

1. Derive explicit criteria from preserved structured observations. Separate normal
   execution, normal path coverage and injected-fault detection. Name each undetected
   fault and its declared change. Failed criteria, not optional mutation traces,
   organize the report. Unknown/incomplete observations remain explicitly unassessed.
2. Add whole-record check inspection with bounded diagnostic text and exact raw routes.
   Preserve raw byte access with unambiguous capture/page completeness. Test long,
   escaped, partial, unknown and multi-failure cases; never fabricate missing content.
3. Display a full account first. Fall back to a labelled prefix only after measuring
   the complete input. The stored account never changes through presentation policy.
4. Retain inspected recovery pages across subsequent reads/operations. Keep their
   designations and explicit visibility if genuine capacity requires a control view.
   Reject acquisitions that cannot coexist rather than quietly rotating pages.
   Refresh source after edits; replacement selection deliberately releases old focus.
5. Put actually visible current-source bodies in one working-set list. Feedback refers
   to that list instead of relocating source. Inventory identifies visible/omitted
   retained extents. Edit authority follows only exact delivered bodies.
6. Present a single verification view containing all scopes, current applicability,
   failed criteria and public submission eligibility. Keep applicable failure reasons
   visible through diagnostic acquisition; historical results remain historical.
7. Add a version-bound region replacement and an optional literal source reply:
   structured header, then a fixed SOURCE separator, then exact replacement text.
   The host resolves old source and serializes transport. Ordinary JSON remains valid.
   No action is extracted from thinking; incomplete replies never execute. No separate
   proposal turn is required. Qualify grammar, parser, wire requests, rejection,
   source authority, stale references, successor checking and exact multiline bytes.

## Work sequence and limits

Keep implementation notes in NOTES.md as work proceeds: evidence, design choice,
failed assumptions/checks, corrective work and governance implications. Avoid making
another governance framework. First implement criteria and view/retention changes;
then integrate literal source transport; finally qualify actual saved-state inputs
and an offline complete edit/check/correction cycle.

Replay C04 and C12/C13 source/observation states without rewriting them. Native
input qualification must include small/full accounts, crowded retained inspection,
actual fault reports and source edits with difficult escaping. A scripted route
must identify the evidence supporting each decision, and remains assisted engineering
evidence. Do not call host qualification a Qwen behavioral improvement.

Run focused regression checks for modified boundaries plus historical compatibility.
Inspect rendered inputs and decoded artifacts directly. Preserve unsuccessful attempts.
Publish the implementation, evidence, limitations and a concise governance update
derived from running notes. Commit and push; verify exact staged evidence and private
runtime exclusion. A future live evaluation needs its own frozen package and allowance.
