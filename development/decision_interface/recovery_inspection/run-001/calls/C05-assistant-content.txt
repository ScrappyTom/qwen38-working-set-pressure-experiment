   Reading the :attr:`port` attribute will raise a :exc:`ValueError` if
   an invalid port is specified in the URL.  See section
   :ref:`urlparse-result-object` for more information on the result object.

   Port validation occurs when the :attr:`port` attribute is accessed,
   not when the URL is parsed.  :func:`urlparse` and :func:`urlsplit`
   return a result object for any syntactically valid URL; the
   :exc:`ValueError` is raised only upon access to the
   :attr:`port` attribute.

   The port must be a non-negative ASCII decimal integer in the range
   0 through 65535 (inclusive).  The following rules apply when the
   :attr:`port` attribute is accessed:

   * An empty port string, as in ``http://host:/path``, raises
     :exc:`ValueError`.
   * A negative port, as in ``http://host:-1/path``, raises
     :exc:`ValueError`.
   * A port whose integer value is outside the range 0 through 65535,
     as in ``http://host:65536/path``, raises :exc:`ValueError`.
   * A port string that is not a pure ASCII decimal integer (including
     strings with non-ASCII decimal digits, such as U+0663 ARABIC-INDIC
     DIGIT THREE, or with any non-digit characters) raises
     :exc:`ValueError`.

   The boundary values 0 and 65535 are accepted without error.

   Examples of the port boundary and error behavior::

      >>> from urllib.parse import urlparse
      >>> p = urlparse("http://example.com:0/")
      >>> p.port
      0
      >>> p = urlparse("http://example.com:65535/")
      >>> p.port
      65535
      >>> p = urlparse("http://example.com:65536/")
      >>> p.hostname
      'example.com'
      >>> p.port
      ValueError: Port out of range 0-65535
      >>> p = urlparse("http://example.com:-1/")
      >>> p.port
      ValueError: Port could not be cast to integer value as '-1'
      >>> p = urlparse("http://example.com:/")
      >>> p.port
      ValueError: Port could not be cast to integer value as ''
      >>> p = urlparse("http://example.com:abc/")
      >>> p.port
      ValueError: Port could not be cast to integer value as 'abc'

   The same behavior applies to :func:`urlsplit` results.

   Unmatched square brackets in the :attr:`netloc` attribute will raise a
   :exc:`ValueError`.

   Characters in the :attr:`netloc` attribute that decompose under NFKC
   normalization (as used by the IDNA encoding) into any of ``/``, ``?``,
   ``#``, ``@``, or ``:`` will raise a :exc:`ValueError`. If the URL is
   decomposed before parsing, no error will be raised.
