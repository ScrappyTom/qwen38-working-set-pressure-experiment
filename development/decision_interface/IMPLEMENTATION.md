# Decision interface implementation

This opt-in successor implements the seven repairs in [PLAN.md](PLAN.md). Existing
configurations retain their defaults and historical evidence. The owner-directed
work concerns host responsibilities; no Qwen preference vote or new task run was
needed to make truthful reporting, consistent lifetime and usable transport concrete.

| Observed burden | Implemented responsibility |
|---|---|
| Failed check did not identify its failed criterion | Derive ordinary execution, ordinary coverage and fault-detection criteria from the preserved observation. Keep unmet criteria in the standing verification view. |
| Recovery split a diagnostic inside JSON | `inspect_check` returns up to four complete criterion records. Large diagnostic text is explicitly abbreviated; exact raw access remains. Raw pages distinguish capture completeness from display completeness. |
| Small account cut unnecessarily | Try the full account first against complete native input. Only measured pressure permits a labelled prefix; stored text and authorship remain exact. |
| Recovery read disappeared on the next read | Retain inspected recovery source until selection replacement. Capacity fallback identifies omitted retained bodies; successful edits refresh them. |
| Source moved between two display locations | All visible current-source bodies occupy `working_set.sources`; receipts carry references. One visibility inventory describes retained and shown extents. |
| Public-check null obscured a current tests failure | `verification.checks` exposes every scope, applicability and assessment. `verification.submission` separately states current-public-pass eligibility. |
| Repeating old code and encoding new code | `replace_region` resolves an actually delivered source region under the current candidate; optional literal source avoids JSON string escaping. |

## Code and boundaries

[`DecisionSession`](../../src/working_set_exp/decision_session.py) subclasses the
existing opt-in host. Its region edit uses the same candidate admission, prospective
input measurement, source refresh, immutable history and declared successor-check
path. Invalid, invisible and stale references reject cleanly. A region reference
does not confer source visibility. Search also returns a mechanically identified
enclosing Python function, including nested methods, so a short match need not make
the actor calculate a complete method's coordinates. Invalid Python retains ordinary
search behavior. Search addresses alone never authorize an edit.

[`check_assessment.py`](../../src/working_set_exp/check_assessment.py) reads verified
preserved observations. The supported `contribution-check-v2` semantics are specific
to this checker family; descriptions of injected changes are separately bound to
the checker fingerprint. Unknown, malformed or incompletely captured assessments
remain unassessed. Custody failure remains a storage error. No formatter can turn an
executed check into a rejected request. Ordinary passing statistics and successful
fault detections do not conceal a failed criterion. Mutation path completeness is
not promoted into a requirement absent from the actual checker.

[`decision_view.py`](../../src/working_set_exp/decision_view.py) generates the complete
visible reference, reply schema and pinned native grammar. An ordinary JSON reply
remains valid. The optional form is one JSON header line, newline, `SOURCE`, newline,
then exact source through the end of the final reply. The host supplies the decoded
`new` field. CRLF, Unicode, backslashes, embedded SOURCE lines, empty deletion and
trailing newlines retain their bytes. The final reply must complete normally; the
runner never extracts or executes thinking. The literal form is not an output-length
guarantee or a mandatory additional proposal turn.

The shared runner gains explicit constraint/decoder hooks. The historical JSON
property-order path remains unchanged when the hooks are absent. Scoped edit policy
resolves the region's path before admitting the complete operation allowance.
Rejected edits trigger no check; executed failing checks preserve saved work.

Retention, input sizing and output construction remain finite. The selected policy
is unchanged at 23,808 input tokens, 56,576 physical context, medium uncapped thinking,
q4 KV and no MTP. No model generation tests that configuration in this package.
The prospective 32,768 generation reserve does not guarantee a final action.

## Qualification

See [RESULTS.md](RESULTS.md) and [NOTES.md](NOTES.md). The task adapter reconstructs
sealed old checkpoints into a separate successor; it never edits the original run.
`qualify.py` sends only native rendering/tokenization requests to the runtime and
intercepts scripted completion fixtures locally. It executes the actual checkers on
separate candidate copies. `verify.py` reconstructs every scripted transition using
preserved observations rather than re-executing checks.

No live-attempt manifest or model allowance is prepared here. A subsequent evaluation
should judge completed supported work under the declared package, with uncoached
selection and actual feedback. This work establishes engineering feasibility,
not a controlled attribution to one wording, tool or retention change.
