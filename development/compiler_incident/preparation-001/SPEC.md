## Task and evidence

The authored selected-function optimizer has damaged two emitted calculation
modules: an inverse-normal call raises an arithmetic exception and a Weibull call
returns a complex value. The task is to repair the supported optimization behavior
and produce a compact, checked incident comparison in `reports/incident.json`.
The actor chooses its acquisition, edit and check order. No reading list, diagnosis,
required first check, incorrect repair or context-boundary instruction is supplied.

The calculation input uses two real functions from CPython v3.12.10, with exact
extraction provenance and the upstream license in `donor/`. The optimizer defect
and captured incident are authored development material; this is not a claim of
a CPython defect or a production incident. The calculation source has no added
data or padding. The three observations contain actual default `ast.dump` output,
with field names and without location attributes: original input, emitted build A,
and emitted build B. The latter selects both functions, overlapping A's selection.
Their captured call outcomes were obtained by executing the original and emitted
trees, not invented from an expected answer.

The candidate has six small text files. The calculation source and full captures
are outside the editable candidate. The existing exact observation tool returns
each complete stored record; no new tool, truncation, semantic selection or
mandatory acquisition has been added. The public check uses independent short
contract examples and validates the report against grader-side comparisons of
the actual saved trees. It does not execute the large historical module inside
the editable compiler during checking, print expected report facts, or expose
the oracle patch. Its ordinary contract failures remain informative.

The work product lists the functions actually changed in each historical build
and the first expression whose AST node kind changed. This is a structural
incident comparison, not a statement that the actor's repair was used by those
past builds. Source alone can suggest the correct optimizer repair. It cannot
establish the requested observed comparison for either build. Keep these claims
separate: this task tests incident-dependent reporting alongside repair; it does
not force an incident-dependent choice between alternative repairs.

Competing explanations include a calculation defect, a selection/scope problem,
and a transformation that changes Python semantics. The original and emitted
trees distinguish transformation from unchanged calculation input; comparing
the two build scopes distinguishes which functions were affected in each build.
The later report and check must agree with those observations. The evaluator's
comparison logic and counterfactuals remain outside every actor input. An actor
that identifies the decisive evidence immediately succeeds; it need not first
adopt or experimentally reject a wrong explanation.

The report is the requested task artifact, edited through the existing guarded
patch operation. A partial report can retain a conclusion before pressure. This
is not a new working-account operation, but it is a real additional copy of
information and must be considered in every continuity attribution. The unchanged
representation still omits private thinking from the very next decision input.

## Offline qualification and vetoes

1. Reproduce the captures, decode their AST notation without evaluating arbitrary
   text, and derive the report from actual tree comparisons. Check the compiler's
   behavioral contract independently of the donor: values/types, signed zero,
   custom unary operators, exception propagation, side effects, literal folding,
   function selection, untouched input and nonselected source, and async scope.
   Reject repair-only, report-only, partial repair, disabled optimization and
   incorrect historical scope. A checker setup failure cannot count as a useful
   negative example; every matrix row must finish the contract cases.

2. Inspect alternate information copies. Combining the two emitted builds does
   not uniquely recover the original lost syntax. Evaluator-side ablations vary
   the original unary syntax without changing either emission or reference-call
   behavior, and vary either build's function scope while leaving the other two
   records unchanged. Those probes establish report ambiguity, not model use or
   a causal performance result. The source-led repair remains the same.

3. Measure six actual-executor paths, including an optimistic minimum that already
   knows the report schema, evidence-first and source-first orders, an incremental
   report, an initial public check, and one partial-repair correction. The schema-
   informed path is a conservative capacity lower bound, not additional knowledge
   supplied to Qwen. Reject pressure geometry if a short evidence-justified route
   completes under 16,000. A verbose oracle route cannot repair that failure.
   These finite scripts do not prove a bound over all possible actor trajectories.
   Lucky guesses, prior source knowledge, algebraic reconstruction and public-check
   feedback may allow a shorter passing artifact; actual use must be audited.

4. On the incremental-report path, fork the exact prefix at its first measured
   boundary. Qualify oldest-prefix admission and actual tool continuation. If the
   original has left the input before the second report edit, recover it exactly
   and verify the recovered body and build B both occur in the next prepared input.
   Record the first build's already-written report as another retained evidence
   copy. This scripted recovery is plumbing/capacity evidence, not a model action
   or a semantic host policy. Preserve terminal rules and version-bound checking.

5. Separately qualify every original observation, stored result and patch payload
   through its actual historical wrapper from an exactly replayed pre-submit
   state. Check bytes, hashes, 22,000-byte admission, candidate/check immutability
   and canonical identity. Forced removal is a plumbing probe, never a natural
   boundary. Save complete requests, native prompts/counts, actions/results,
   candidates, source identities and runtime custody. Seal unsuccessful attempts
   rather than replacing them.

## Decision boundary and interpretation

This preparation can establish a usable report-and-repair task, natural input
pressure along short justified paths, and exact continuation under actual limits.
It cannot establish Qwen's investigation ability, successful inference at those
limits, retention of a hypothesis, failed-repair recovery, or an interface benefit.
The optimizer fault may be found directly from source; the report is deliberately
part of the contribution being tested. Do not call an AST-comparison result proof
that the actor changed its explanation after contradictory execution evidence.

Before model exposure, bind a separately reviewable execution runner to this exact
package, strict completion custody, monitoring, one action per request, authentic
fork/admission, no retries/rescue, and the bounded owner-approved scope. Current
authorization ends at preparation. Do not launch another consultation or ordinary
pilot just because the task passes its offline checks.

After any eventual run, directly read all inputs, thinking, final actions, results
and following host decisions. Identify evidence before and after the boundary,
the exact later decision it informed, and copies in captures, source, report,
patch arguments/diffs and check feedback. Distinguish never-retained reasoning,
evidence removed at pressure, and misused available evidence. Keep task outcome,
first-check result, remaining correction opportunity, necessary reacquisition,
avoidable repeated work, native input processing, generation and loop time separate.
Preserve consequential misunderstanding and then consult Qwen separately before
settling a presentation change. Neither a long response nor a possible wording
alternative obliges a change; retaining the interface remains a valid outcome.
