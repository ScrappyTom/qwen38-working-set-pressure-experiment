## Question and task

Can Qwen complete a fresh investigation while correctly distinguishing the
original report from its own repair and subsequent verification? This is task
development with the consulted presentation, not a framing-only comparison or
a context-pressure study. A different task/domain also changes the conditions.

The authored Shift Ledger fixture reports time per employee for one local day.
Its task describes an earlier confirmed night shift whose contribution is
missing from the following day's report. The task text is fixed before the
repair session; the session begins with no recorded actions. The source has
nested API, decoding, calendar-window and reporting modules plus a small CSV
example and ordinary README. No files are added to manufacture context load.

The initial model input contains the task and normal root orientation, without
a diagnosis, reading list, failed check, oracle sequence or repair fragment.
Qwen may use the existing source/navigation/search tools and public check in any
order. It need not adopt an incorrect hypothesis or check before editing.

The frozen public checker uses explicit expected outputs, not donor identity.
Its 24 cases cover decoded instants, the report window, overnight and spanning
contributions, neighboring dates, exact/touching boundaries, ordinary and combined
shifts, additive overlaps, void exclusion, fractional minutes, equivalent
representations, a negative reporting offset, empty input and invalid shifts.
It reports intermediate decoding/window facts and behavioral totals. These can
distinguish parsing/window-construction explanations from reporting behavior;
they do not name a broken source line or supply a patch. They are intentionally
informative public diagnostics, limiting claims of unaided discovery.

The initial source fails seven reporting cases. An offline partial repair that
admits overlapping shifts still overcounts time; a complete clipping repair
passes all 24. These oracle examples are preparation evidence only. Neither
their actions nor conclusions enter the actor's initial state. Successful
submission is assessed using the actual current-candidate public check and a
direct final-source review; the host still permits unchecked submission and
does not force success. There is no hidden grader or universal-correctness claim.
