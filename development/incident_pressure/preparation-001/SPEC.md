## Candidate: an export selected under the wrong agreement

This is an authored preparation fixture, not a production incident. The Posting
library has two valid calculation policies: round each line before summation,
or sum exact amounts before rounding the statement. Two deployment jobs select
policies. The reported discrepancy could involve decoding, arithmetic, or the
effective job assignment. Source describes valid operations but does not encode
the external receiving agreements.

The actor receives a symptom and readable observation-directory identities. It
can retrieve the captured execution and receiving agreements through the existing
exact observation operation, or obtain current diagnostic output through the
public check. Both routes expose evidence relevant to the investigation. The
directory does not announce the diagnosis; the public check reports actual
execution and contract failures without giving a replacement fragment.

Two offline worlds share byte-identical task and candidate source/configuration.
They differ in which job was captured and which receiving account requires line
rounding. A correct targeted configuration change in one world must fail the
other, and changing both jobs must fail both because it damages an unaffected
agreement. This counterfactual tests whether incident evidence is necessary to
identify a justified correction. It does not prove that a model consulted or
understood that evidence. A lucky guess remains possible.

Qualification must reproduce each capture through actual application execution,
test both policies against explicit expected values, reject wrong-job/global
changes, and preserve decoding and negative/zero/rounding boundaries. Public
expectations must not come from a donor's repaired implementation. Preserve
these evaluator-side findings outside the task input. No source change is needed
if the defect is a deployment assignment; a configuration repair is useful work.

## A pressure veto, not an extended walkthrough

Measure three concrete routes in each world: a short route using public-check
evidence; a short route using the two saved observations; and source investigation
through the actual imported components. Every action goes through the real
executor. Save all requests, results, successor identities and check opportunities.
The scripts know the correction; they are capacity probes, not actor trajectories.

An efficient justified path completing below 16,000 refutes a claim that this
candidate necessarily crosses that boundary. A longer route crossing it would
not repair that defect. Reject this candidate for the primary pressure study if
the short paths finish below the proposed limit. Do not lower the limit, add
unneeded files, enlarge captures, impose reading, or run more model calls to
salvage it. Preserve an information-dependence pass separately from a pressure
failure. The existing governance prerequisite for a fresh ecological pressure
fixture is not waived by this preparation.

Also force payload removal **offline only** and exercise exact saved observation,
result and patch recovery. Validate complete serialized wrappers, exact original
bytes, candidate/check state and canonical provenance. A forced plumbing probe
does not count as a naturally reached context boundary or actor recovery.

## What would justify proceeding or changing something

A live pressure package needs an eligible task, evidence of useful work across
the proposed boundary, exact recovery and branch-continuation qualification,
coherent native capacity, frozen custody and bounded execution safeguards. If
this candidate fails the pressure gate, preserve it as a rejected preparation
candidate, without another ordinary-loop run by default. Prefer an incident in
an existing substantive codebase over inflating this authored example.

After eventual exposure, read every actual input, complete thinking, final
action, tool result and following host decision. Establish when the decisive
evidence was acquired, what changed at pressure and what later choice depended
on it. Inspect duplicate information in task, source, checks, edits and results.
Private thinking omitted immediately was never retained through that channel;
do not label its later absence a pressure loss. A correct repair that embodies
the conclusion may make later recovery unnecessary. Rejected explanations must
be inferred from actual interpretation and actions, not imposed by the oracle.

Report task correctness, first-check outcome, remaining correction opportunity,
necessary recovery, repeated work, peak/cumulative input, output and complete-loop
time separately. A failed-repair recovery study remains a separate question.
Keep learning with Qwen available for consequential misunderstanding or recurring
cost with a plausible remedy; no dialogue is earned merely by a long response.
Retaining the current interface remains a complete design decision.
