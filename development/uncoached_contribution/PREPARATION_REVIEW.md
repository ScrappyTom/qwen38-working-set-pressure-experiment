# A useful contribution through an uncoached loop

The automatic runner is integrated and qualified offline. The prepared task asks
Qwen to extend the saved parser backport with meaningful copying/serialization
regressions while preserving the completed library, parsing regression and
documentation. This tranche sends zero Qwen completion requests. It establishes
apparatus feasibility, including a broad-reading route; autonomous selection,
actual combined-reply use, completion cost and reasoning allocation remain untested.

## Why this contribution

I inspected the exact saved source in parser-documentation/turn-04, rather than
inferring missing work from check counts. In Lib/test/test_configparser.py,
test_multilinecontinuationerror at lines 1852-1862 checks the exception raised by
the real parser, including the required allow_no_value configuration. Unlike the
neighboring exception methods, it does not copy or pickle that exception. The
new task tests whether restoration preserves its diagnostics, with and without
a final newline, across copy, deepcopy and every supported pickle protocol.

This is additional coverage on reused real source, not a novel bug investigation
or a repeated attempt at the completed documentation task. The initial candidate
is the exact saved fbfc4f7a version and its 39 archived actions. The selected
working group starts empty. The task names the behavior and test file, but supplies
neither a solution nor a reading list. Constructor, exception, parser and existing
test source are accessible through the ordinary tools. The offline reference
never enters the proposed live initial candidate or model input.

Acceptance runs the 356 saved tests, edited tests and eight earlier contract
tests; preserves all nine non-test files byte-for-byte and existing test methods'
syntax trees; observes actual parser-raised exceptions undergoing the requested
transports; and runs only the added methods against four restoration faults.
The faults change source, line number, raw line or errors-list state. Merely
calling serialization is insufficient. The reference adds one method, passes
the 357-test edited suite (five skips), and detects all four faults. These are
regression-quality checks, not an exhaustive proof of every requested assertion.
Post-run source review must still assess scope, diagnostics and unintended changes.

## What the runner now does

run_uncoached_contribution.py reuses the bounded host and native lifecycle. It
preserves the corrected ordered wire request before sending, and the exact raw
response before parsing. A requested edit/check pair executes as two archived
operations; the host binds the check to the accepted successor and presents both
actual receipts in the next admitted input. A failed check preserves the edit;
a rejected patch skips its check. Neither explanatory text nor private thinking
is carried into subsequent decision inputs. There are no reviewer messages.

Request and operation allowances are separate. A pair that cannot fit the
remaining action allowance stops before mutation. Discussion-only output closes
without submission or a coaching response. An operator stop drains a returned
reply's declared operations, then closes and seals; transport/processing failure
preserves the received evidence and current work without retry. Runtime and
source identity checks remain enforced. The initial rendered prompt explicitly
describes this behavior and current-check scope, alongside complete tool forms.

## Decision

16 model requests and 24 actual operations, with no automatic retry. This is
ready for the separate execution step; run-001 does not yet exist. Preserve

unresolved question. No new consultation or reasoning comparison is warranted
by the offline success alone.
