# Host path audit

The complete candidate and archive survive this attempt unchanged. All eight
actions replay exactly against the frozen host using the actual recorded native
sizes; no approximate tokenizer or new model request substitutes for them.
The bounded view keeps six recent rows plus current state, selected source,
saved-result pages and feedback. Earlier private thinking is never carried into
the next two-message request. History scaling and atomic-edit feasibility remain
offline qualifications: Qwen executed neither work_on nor patch in these eight
actions, so the pilot does not qualify their successful use.

The main defect is an unspendable acquisition reserve. `CONTROL_ROOM=1024` was
applied after recovery and ordinary feedback, effectively adding a 22,784 ceiling
inside the declared 23,808 input ceiling. Actual saved native trials prove the
following without a hypothetical token estimate:

| Operation | Complete next input | Actual input room left | Frozen outcome |
| --- | ---: | ---: | --- |
| C04 recover the 1,151-byte check | 23,348 | 460 | Rejected |
| C05 deliver one documentation search match | 22,838 | 970 | Status-only feedback |
| C06 recover that search | 22,784 for selected page | 1,024 | Only 53 of 335 bytes returned |

C04's full trial is I0016. The host shrinks all the way to one byte, still costing
22,816, and returns an error at I0027/22,732. C05's complete I0028 contains the hit
at documentation line 1369; I0029/22,800 sent to C06 omits it. C06 receives an
exact prefix ending inside the candidate identifier, with next_offset=53. The
original query and hit remain absent. These are admission-policy failures to
provide useful evidence, despite exact storage and correct byte boundaries.

C07's ordinary next test-page request is rejected beside the retained full
library and first test page. C08 repeats the historical-check request and is
rejected again. No acquisition or edit is committed on these rejection paths.
Selected sources are never silently evicted. That protection is useful, but
these retained broad sources plus the reserve policy obstruct later evidence.
It does not establish that the selected set was the smallest useful set or that
Qwen could not choose a better group.

The correction prepared in isolation lets feedback, historical pages and complete
edits spend acquisition headroom, while enforcing the actual hard ceiling. Bulk
source reads prefer the reserve and fall back to the hard ceiling only when no
requested page/group fits the preferred target. Selected source remains intact.
Actual-state counterfactuals at C04/C05 deliver the exact full inputs above; Qwen
has not seen those counterfactual inputs. This is prospective host qualification,
not a behavioral rescue or proof of saved model time.

Two additional offline defects were reproduced and corrected prospectively:
file-filtered history omitted work_on's nested source paths, and an unsupported
candidate line could escape as CandidateError instead of a clean rejected edit.
Neither occurred as an executed Qwen failure. The original probe and failed test
are preserved; the final 23 selected host/runner tests pass. See the separate
capacity-repair-001 record after its integration.

C08 also exposes a deferred decision-view issue: recent search rows keep the
path but omit the query. Its mistaken query reconstruction concerns an absent
fact. Adding a minimal operation description could be justified, but this audit
does not silently add another field or attribute the entire long response to it.
