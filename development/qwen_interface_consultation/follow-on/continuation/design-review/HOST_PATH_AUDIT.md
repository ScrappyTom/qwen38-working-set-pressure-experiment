# Design host-path audit

The selected q4/56,576 runtime and frozen request bytes were retained for all
four fresh design conversations. The continuation manifest binds the unchanged
original package, preserved Q1 seal/review, owner monitoring amendment and 44
source identities. The direct qualification decision was checked before D1.
All requests were nonexecuting system/user pairs with seed 42, no carried answer,
thinking or prompt-cache reuse, and no action output channel.

The model received the actual complete ordinary states plus implementation facts
and the full action grammar as visible design material. It was explicitly asked
to keep requirements visible and to distinguish presentation from new behavior.
The design instruction asked for a concrete catalog, state fragment, mappings,
presentation tiers and retained protections in each independent example. That
scope helps interpret the long proposals; it does not explain their repeated
thinking by itself or measure an alternative prompt's effect.

Raw endpoint bytes were stored before parsing, with exact separate thinking and
final artifacts and a nonexecuting host result. Every output finished normally.
The following host decisions sent D2, D3 and D4, then closed/sealed the stage.
The design runner reports reserve overruns but does not cap or reject a normally
completed answer for exceeding the admission reserve within this fixed stage.
Reconsideration applies prospectively before the next stage; no retry or rescue
was added. Runtime failure, truncation, lost telemetry and transport failure
remained stop conditions.

[Independent verification](VERIFICATION.json) checks 32 public files, 3 private
runtime files, 25 records, exact package/rendered bytes, source identities,
native/endpoint/offline input counts, separated response bytes and zero cache.
Full offload, q4 K/V, 56,576 context, no MTP and no context shift match. The server
closed and the port was free. A final read-only /slots monitoring poll met the
already-closed server and received connection refused; this was after normal
completion/shutdown, not a failed model request.

## Proposal-to-implementation checks

- D1/D3: an event address is not necessarily a saved action-payload handle.
  The actual read events display present=false and canonical_source=null for
  action_payload. Their executor payload maps are empty. Reopening the proposed
  EVT-0001 returns tool_rejected/event handle is unavailable. This is a defect
  in the proposed model-facing projection, not an existing host acceptance bug.
- D2: the full two-line successor file is reconstructable from the resident
  diff; exact bytes and current hash match. No new read action exists, but
  absence of that action does not establish loss of the current text. The
  internal complete_reads/read_coverage remain after patch; only check flags
  clear. A new version-aware coverage view needs explicit semantics.
- D4: reopen_event returns a wrapper containing only saved old/new in
  action_payload, plus handle/hash/size. Original candidate/file/path guards
  remain in the resident event signal. Its proposed wording incorrectly puts
  them in the retrieved object. It also cites a candidate_id field absent from
  active_user_authored_step, although the correct ID is elsewhere in the input.
- D1/D3 catalogs assert completeness but omit required accepted-form detail.
  D2/D4 are more explicit, yet still require comparison against the actual
  schema and host byte/stage/handle constraints. Model-authored documentation
  is not an executable source of truth.

These checks are saved in [CONTENT_CHECKS.json](CONTENT_CHECKS.json). They execute
only isolated offline fixture operations after the response seal. They do not
provide feedback to the model or convert a design response into a live action.

The selected preparation adds one visible tool-reference block. It changes the
information available during deliberation, so it is a behavioral intervention,
not a neutral refactor. It keeps the host, operation names, state/source bytes,
required guards, output grammar and exact custody intact. No proposed secondary
state ledger, automatic read suppression, canonical-store change or new tool
is adopted. Required argument information remains a future-interface baseline
requirement even if a later latency comparison is neutral.
