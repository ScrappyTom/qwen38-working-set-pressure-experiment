| Peak input | 18,714 | 20,389 | +1,675 |

Prompt processing and decoding have different costs; summing their tokens is
not a compute-equivalence measure. Request time includes prompt processing and
generation but excludes the subsequent local tool execution and audit. The
comparison offers one action per state, so it cannot price the extra later
check required after a confirmation read or otherwise establish whole-task
efficiency. There are no completed submitted tasks in either condition.

C15/C16 accounts for 55.1% of the output reduction and 57.3% of the elapsed-time
reduction. Retaining that pair is required. As an explicitly post-hoc sensitivity
description, the other seven pairs still show generation 22,530→14,609 (−35.2%)
and elapsed time 1,304.766→931.233 seconds (−28.6%), but input-plus-output rises
71,126→74,930 (+5.3%). The aggregate token saving therefore depends on the long
tail pair. This is a small development sample, not a stable speedup estimate or
a reason to discard an inconvenient response.

The actor preserves several useful distinctions: all I1 responses recognize
the recorded reading; the I2 responses distinguish old-check A from edited B;
all I4 responses recognize the partial source read. C11 applies the intended
guarded repair. Exact storage, version protections and retrieval remain a useful
foundation. No stale check, malformed action or false submission occurred.

The [host audit](HOST_PATH_AUDIT.md) also preserves the issues that success could
hide. Resource wording still becomes procedural instruction, including in
reference responses. The permanently incomplete root plus an imperative and
missing paging requirements contributes visible friction in C15. Correct sizes
for different objects still invite scope confusion. I2 rereads confirm source
already present in a resident diff. These findings do not justify suppressing
rereads or replacing the information store.
