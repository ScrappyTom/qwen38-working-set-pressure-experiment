# Host-path audit — visible tool reference comparison

The run completed all sixteen frozen requests without an execution, transport,
capacity or custody stop. Independent replay reproduces every actual action
result and before/after candidate/session snapshot. This validates execution;
it does not make every accepted action useful or every model interpretation
correct. The [direct audit](DIRECT_TRANSCRIPT_AUDIT.md) covers every response,
including successful and recovered paths.

## Execution path and limits

The separately frozen runner first verifies the original prepared package, seal,
source closure and execution manifest. It natively renders and counts all sixteen
requests before dispatch. Every request then gets a newly reconstructed host
state, whose original request, candidate and session must match preparation.
Only the single added system reference differs between paired native inputs.
No prior model response or executed result enters the next conversation.

Raw endpoint bytes are saved before interpretation. Separate thinking/final
fields are saved before finish, accounting, channel and health validation.
Only a complete strict final action reaches the existing executor, once.
Actual after-state is saved even on an unexpected executor exception; none
occurred here. All host_decision records have processing_stopped=false.
The existing DevelopmentState.execute also records each action/result pair;
there is no subsequent rendering of that pair to the actor in this study.
The public receipt preserves the action/result and resulting candidate/session.

The six checks comprise one new passing check on edited I2 candidate B and
five baseline failures on unrepaired I1/I3 candidates. All are accepted executions,
not rejected requests. The C11 patch is the only mutation; it correctly changes
return 1 to return 2 and leaves the public-check flag false. No submission or
additional response was offered. Stopping each state after one action is the
prospectively specified host boundary, not model abandonment.

The frozen input's original fixture allowance is still displayed: 13, 21, 23
and 22 calls remaining in I1–I4 respectively. Counting the imminent check leaves
12 in I1, 20 for I2's check and 22 in I3's checks. These are hypothetical
continuing-fixture allowances. In this comparison the host offers no actual
correction turn after a failure; no claim of available live correction opportunity
is made from those resource fields. No budget, output cap or stopping policy
was changed during execution.

## Missing requirements concealed by accepted final actions

Legacy input shows brief descriptions and available names; the action schema
is an endpoint response_format constraint, not ordinary model-visible instructions.
C01 guesses handle versus event_handle. C04, C09 and C12 favor a check without
a candidate guard in thinking, while their actual finals contain the correct
required guard. C15 repeatedly plans a parameterless p0_page; its final includes
path and offset. There are no executed malformed requests in this sample.

The reference makes all required forms, limits and effects visible. Its responses
use the actual forms rather than debating unknown argument names. C11's thinking
and final both identify the pre-edit guards and successor check requirement.
These observations support the intervention without claiming the server inserts
semantic values or that the grammar caused a particular choice. The actor still
generates the final values under the output constraints. Formal acceptance alone
would have missed the interface burden.

Retain complete tool information for future interfaces. The measured intervention
is the whole reference and its system placement, not signatures alone. Returning
to undocumented requirements is not a valid response to mixed performance.

## Descriptive resource wording remains procedural in both conditions

The actual user state contains a correction-cycle illustration saying a
check–patch–recheck–submit sequence fits an ideal path. The executor does not
require a baseline check before patching. C03/C04, C09/C10 and C12 repeatedly
treat the illustration as evidence for the expected next action. C09 says it
overrides ambiguity; C10 retains that reading despite complete tool contracts.

The selected baseline checks are legitimate diagnostics. Their failure on
unrepaired source is expected, and nothing here proves they are wasted checks.
The demonstrated mismatch is assigned procedural authority and repeated
deliberation over an illustration. C11's accepted direct edit demonstrates that
the executor permits the alternative. Thinking does not quantify how many
tokens the wording caused or prove that a different sentence would fix it.

A future narrow wording change should state remaining resources without
prescribing an example as the next step. Keep that separate from the completed
reference comparison; do not suppress baseline checking or add a new actor policy.

## The root's incomplete flag can encourage unhelpful paging

The common system instruction says to use p0_page when the repository view is
incomplete. build_p0_root always sets complete_for_repository=false, including
the one-file toy repositories, while complete_for_top_level=true. The flag means
the root is an orientation view, not that a global completion condition can be
satisfied by a parameterless or stateful page advance. p0_page actually requires
a path and a zero-based row offset. It returns a scoped structure or symbol page;
it does not change this root flag or supply exact source/read coverage.

C15 initially understands the missing source and historical marker, but then
repeatedly treats the root flag as a mandatory next operation and guesses the
paging interface. Its final requests service.py offset 1. The actual host
correctly returns only ready(), lines 7–8, the second of two symbols. That
function's exact source was already in the input. The result adds outline
count/paging metadata but neither the missing source nor the old marker, and
coverage remains 7–8. This is the clearest observed weak progress hidden by
acceptance. The thinking never specifies offset 1, so its origin is unresolved.

C16 instead reads from line 1, extending coverage to 1–8. C13/C14 do the same.
All four recognize the partial read. Thus C15's weak acquisition cannot be
diagnosed as believing complete=true meant the whole file had been read.

The combination of an imperative, a permanently incomplete orientation flag,
and undocumented paging earned this finding. The reference clarifies paging
forms, but the shared wording remains. A later change may clarify scoped
navigation and its completion semantics. It must not hide structure by inferred
relevance or be described as behaviorally neutral.

## Object scope and source confirmation remain distinct concerns

Source bytes, serialized extracted-field objects and complete saved results have
different sizes and hashes. All can be correct simultaneously. For the actual
I1 recoveries, importers.py has 2,099 source bytes, a 2,304-byte content-field
object and a 2,687-byte full saved result; saved_runs.py has 9,505 / 10,164 /
10,549 respectively. C03 (reference) sometimes uses the field-object count as
source size. C07 (legacy) combines this scope confusion with incorrect manual
character counts, then partly recognizes canonical payload sizing. C15 uses
the 45-byte content-field object as the length of the 29-byte ready() source.
No changed source or failed hash validation results from these statements.

The reference describes full-result retrieval accurately, and C02 explicitly
predicts it correctly. The presentation still places different object scopes
near one another. Accepted access cannot establish that all displayed metadata
is understood. A later scope/grouping variant needs exact host-generated records
and an interpretation or subsequent-use observation, not acceptance alone.

I2's full successor file is already present in its resident diff. C05/C07/C08
read it again under the task's current-source wording. These are post-edit
confirmation, not recovery of absent source. C08 expressly considers the diff's
sufficiency before selecting read. C06 instead runs the necessary new check on
B and passes. Neither the conserved read_coverage/complete_reads fields nor
current source presence automatically dictates the actor's choice. In particular,
those internal read fields persist across patching; they are not new
version-aware proof of post-edit reading. The current check flag is cleared by
patching and rebound by an actual new check as documented.

No blanket reread suppression, new coverage/check fields, generated state view,
summary or memory mechanism is earned by this comparison. Accurate grouping
remains a deferred design idea, not a rejected category. Prior model-generated
views were rejected as written because their examples were false.

## Preserved conclusions

Exact version guards, full historical records, canonical handles and the
distinction between retrieval and execution remain useful. This run has no
invalidating implementation defect on the exercised path. The incomplete legacy
interface and shared wording still impose observable friction. Preserve both
facts, qualify the reference decision to these development states, and carry
the earned wording/scope issues forward without changing this sealed evidence.
