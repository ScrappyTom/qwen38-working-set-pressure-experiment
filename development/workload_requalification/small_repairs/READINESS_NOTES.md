The read-only portability review found three earned defects and one further
apparatus inconsistency during their correction. Earlier qualification folders
remain unchanged.

1. Preparation checked only prerequisite output hashes. It did not establish that
   qualification passed on the current source closure or bind those prerequisites
   into the live freeze. The earlier checker qualification binds an older
   repair_task.py. New prerequisites check status, complete source closure, source
   bytes, aggregate inventory, every recorded output's size/hash and the expected
   original/reference or native-grammar outcomes. Their sealed outputs and seals
   enter the task's source binding. Qualification itself records implementation
   identities without recursively depending on its own future seal.
2. A complete-looking case summary could hide an incomplete outer execution. A
   read-only counterfactual using saved passing shift stdout with timeout metadata
   produced passed=false, no failed criteria and no displayed termination reason.
   The revised report keeps each observed case and adds an explicit uncompleted
   public-execution obligation, with actual termination, return code and capture
   status. This is a counterfactual boundary finding, not a recorded Qwen failure.
3. The initial small-repair view dropped the task-author relationship previously
   established by the episode-framing consultation. The new annotation says the
   incident reported in task precedes this repair session and distinguishes it
   from recent_activity and retrievable operation history. It does not modify task
   bytes, supply a diagnosis or claim any repair succeeded.

   accounted decision grammar has no such reply form. The old fifteen native
   cases never tested it. The draft did not reach a model. The repaired package
   uses an explicit edit, a later public check, and submission. It retains the
   current host and 24-request/72-operation allowance. The seventeen-case native
   vocabulary qualification accepts an explicit patch and rejects the same reply
   with unsupported check_after appended. This is
   an apparatus correction, not restoration of a combined-check feature.
