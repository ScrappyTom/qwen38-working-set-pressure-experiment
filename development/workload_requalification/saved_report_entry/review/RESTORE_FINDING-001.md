# Closed run 001 checkpoint reconstruction finding

The original live run and frozen source remain unchanged. This finding arose after closure during exact replay; no model, native-tokenization or checker execution was performed for the diagnosis.

The verifier reached all recorded operation/checkpoint comparisons, then `saved_report_task.restore` rejected the final snapshot with `checkpoint phase accounting or exact reconstruction differs`. A read-only Python trace captured the reconstructed session at that exact exception. The phase counters were valid: phase 2 had used four of eight requests and five of sixteen actor operations; six cumulative requests, seven actor operations, nine new assisted operations and nineteen archived operations were recorded.

The sole differing snapshot field was `diffs`. The exact three diff values were unchanged. The saved JSON had string keys `"2"`, `"8"`, `"16"`; reconstruction intentionally converted those keys to integers `2`, `8`, `16` for host lookups. The subsequent canonical-JSON byte comparison sorted the former lexically and the latter numerically. It therefore compared orders `16,2,8` and `2,8,16`, although the restored mapping represented the same diff records.

This is a checkpoint serialization defect triggered by multi-digit operation addresses. It is not a phase-counter failure, an account-authorship failure or an artifact/check failure. The closing account and submission happened after the report edit at operation 16; that edit supplied the key ordering crossover.

The initial prospective suggestion was to normalize serialized diff-map keys at the snapshot boundary. Further review identified its historical-byte cost. The adopted plan instead prefers task-local typed normalization of incoming diff addresses for the existing reconstruction comparison, retaining integer runtime keys and the historical snapshot serializer. The exact reconstruction assertion remains. Qualification covers a real multi-digit report edit, a final account plus submission, and tampered diff values/addresses; it must not replace the byte comparison with broad permissive equality. Roundtrip also does not authenticate arbitrary changed values: cross-bind them to their accepted archived patch receipts. See `RESTORE_REPAIR_PLAN.md` for the published boundary.
