# URL checker capture and interpretation boundary

This is a task-local prospective adapter, not a change to the historical checker or a new acceptance policy. The original fresh attempt ended during acquisition and produced no current checker diagnostic. The reasons for this capture adaptation come from inspecting the actual original checker/helper and the previously earned shared observation boundary.

Pure assembly reproduces all three original generated checker definitions exactly: tests `feb620566b116cba4e542d929f92fbcbd8a25a42656f41d8773d30583314d2cf`, examples `63d69f2458f46c39bf35a7567f3cc8e2b203db3050f0e7add4be8939af422c25`, public `f68215eea0ca2421f56b28023ea51702b59c6faa3ae5b6e2a023450786543627`. Source factory, checker tail, example helper and original six-file candidate are independently pinned before revised assembly. Assembly and syntax checking are not checker execution or model evidence.

The original checker loses observations at three places: `run_suite` retains only the last 700 characters of one failure/error, the doctest helper retains only its last 2,200 characters, and the final 6,500-byte report reduction can remove details from real failures and injected-fault runs. The successor retains every complete suite failure/error and runner output, complete doctest output and complete structured stdout before host presentation. It does not change the ordinary execution, path collection, seven fault definitions, preservation, doctest selection or acceptance expressions. The normal acceptance functions remain AST-identical.

The existing `ObservationStore` preserves the actual streams and execution outcome before `url_reports` derives a bounded report. Its storage/capture limits still apply and are reported as actual limitations; this adapter does not promise unlimited exact recovery. An incomplete or unsupported observation carries actual termination, return code, a bounded uninterpreted diagnostic and exact raw access. It is not converted into invented URL criteria or fault findings.

Interpretation separates three facts. A real candidate failure is an unmet normal criterion. An injected suite can execute and not succeed. Only after the ordinary execution and required normal path coverage pass does that latter outcome establish detection under the original aggregate rule: at least one test ran and the injected suite was not successful. It is not silently strengthened to a failure/error-count predicate or to per-target detection. Missing paths during mutation runs are not additional requirements.

When the control is inadequate, the report explicitly says the injected suite executed but detection remains unestablished. Those rows have `met=null`. Failed-record counts include only `met=false`; unassessed records are counted separately. Both remain visible, with real failures first. No optional-row suppression policy was introduced.

The `tests`, `examples` and `public` scopes remain different evidence. Tests-only success does not certify added examples or prose. Executable examples do not validate all explanatory prose. Authored tests and accounts are not executed observations. Original preservation checks and independent final review remain required; adding capture metadata does not strengthen their substantive coverage.

API: `checkers.original_checker(scope)` returns exact historical definitions; `checkers.checker(scope)` returns the successor capture definition; `checkers.contracts()` binds the actual successor hash and original acceptance hash; `url_reports` implements the existing assessment/overview/inspection interface. CPU verdict and information-path qualifications, and pinned native request qualification, are separate from this source-boundary note and must pass before exposure.

This is checker/report and scripted information-path evidence, not actor performance. Earlier unsuccessful evaluator forms remain recorded separately.
