# Lessons from the coverage repair and completed contribution

These are observations for subsequent governance updates, not new actor-facing
requirements or a change to a frozen experiment.

1. Qualify what a checker claims, not just whether it runs. The earlier ordinary
   pass and silent-selection probe did not establish exact exception class or
   diagnostic assertions. Use meaningful counterexamples for the actual contract,
   including each distinct site where a stronger assertion elsewhere can hide a
   weak one. Candidate tests must pass before mutant failure counts as sensitivity.
2. Keep ordinary behavior, authored coverage and fault sensitivity separate.
   Expected mutant failures are positive sensitivity evidence. The host must not
   describe them as current-candidate failures or declare there are no faults
   when the registered checker deliberately executes them. Preserve exact raw
   observations before reducing the report.
3. Match preservation to the real task. New methods inside an existing class are
   legitimate. Protect the original method bodies/assertions without requiring
   a new class or byte-identical formatting that the assignment never specified.
   Direct review still assesses retention of semantic scenarios.
4. Evaluate fixtures as carefully as production. Preparation caught a real
   cumulative-counter omission, mistaken fixture expectations and a route check
   looking in the wrong field. Preserve failed qualifications and fix the actual
   responsible layer. A researcher's supported scripted route remains feasibility,
   not model capability. Review what in each actual input justifies the next step.
5. Keep current operational facts separate from account meaning. A pre-edit
   account can become stale immediately after its companion edit. This run
   resolved that status using current source and actual receipts, then updated
   the account after the pass. Provenance does not automatically refresh its
   interpretation, and this result does not justify mandatory account rewrites.
6. Successful artifacts do not validate every private explanation. Here the
   selected implementation tail establishes the raise, while an invented MRO
   explanation goes beyond the available evidence. Record the precise gap and
   consequence. Do not convert it into a blanket memory/interface diagnosis or
   a compulsory consultation when no consequential wrong operation followed.
7. Count complete work and distinguish branches. The two presentation arms keep
   their narrow historical scores. The test-only successor supplies verified
   review findings and completes one branch; it is not an extra matched seed,
   a fresh autonomous solution, or a corrected score for the other branch.
8. Keep costs and opportunity intervals explicit. New requests/operations differ
   from cumulative history. Input processing, generation, host/apparatus work and
   independent review differ. A correct contribution with long construction
   remains costly; a shorter response alone is not the success criterion.

The next workload should require a new decision from saved work plus newly
obtained evidence, with ordinary recovery available. It should preserve useful
prior work without forcing a wrong repair, mandatory note or artificial eviction.
Consultation stays outside active runs; prospective checks and policies must be
declared and qualified before exposure. The broader workload ledger remains open.
