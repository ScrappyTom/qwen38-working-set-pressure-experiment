# Draft repair boundaries from the live acquisition evidence

Not a change to run001. Close, seal, directly review and publish that attempt
before implementation or any successor exposure. Reassess this draft against its
remaining responses. No final performance diagnosis is assigned to an open call.

## Demonstrated missing distinctions

- C17 and C18 see an individual returned page beside a merged selected view,
  both expressed using returned_start/end fields. The recent earlier read records
  retain requested coordinates, not the old actual extent. C17 incorrectly assigns
  the merged extent to one earlier read and therefore treats a new line as a
  duplicate. C18 again finds the two scopes confusing.
- The host knows it reduced a page to fit the chosen next-input allowance, but
  the latest receipt exposes the extent without that sizing reason. C17 speculates
  about blank lines or incorrect file metadata. Generic end=0/pagination warnings
  do not report the actual cause of this operation's small return.
- C15/C17 equate one operation with one source acquisition. work_on already reads
  multiple requested paths/ranges, including previously unseen source, in one
  operation. Its reference foregrounds replacing selection rather than acquiring
  a group. Do not add a new batch tool to duplicate that existing capability.

## Minimal prospective implementation

Retain exact storage, source identities, version/edit guards, selection policy,
recovery, accounts, checks, reply grammar and reasoning policy. No automatic
source relevance decision or semantic summary is proposed.

1. At the current host's acquisition recording boundary, preserve mechanical
   requested versus returned extent facts and identify a page reduced for the
   complete proposed input. Distinguish a user-selected subrange from capacity
   paging. A complete requested range is not necessarily a whole file. Keep all
   exact source bytes and historical receipts intact.
2. Include those facts in the compact latest receipt, not only in an archived
   object that the actor would have to rediscover. Define the source view as the
   current selected extent, which can merge acquired ranges and refresh after an
   edit; distinguish it from the producing operation's individual page. Preserve
   actual origin and scope rather than implying that the merged view was returned
   by one earlier request.
3. State work_on's existing multi-source acquisition effect plainly in the actual
   operating reference. Do not imply arbitrary adaptive multi-operation replies,
   guaranteed whole-file delivery, preinspection, or relaxed editing authority.

Crucial admission rule: construct any added receipt/view facts before measuring
the complete proposed next input. Appending even truthful metadata after fit
validation would recreate a capacity bug. A wrapper around the returned result
after the parent operation commits is therefore unsuitable.

## Qualification

Use real saved C16–C18 states as information-path fixtures, plus small full-range,
user-subrange and capacity-paged controls. Confirm why a page is small, what the
current merged range represents, and which source actually reaches the next
input. Preserve distinct account success/read rejection. Confirm two previously
unread small sources can be acquired by work_on together and then satisfy the
ordinary source guard only after actual delivery. Keep selected material and
candidate unchanged on a rejected replacement.

Use native sizing for the crowded saved states after the CPU checks. New metadata
may change exact fit or trigger existing recovery; report that actual transition,
never assume an old near-ceiling input still fits. Do not change numerical reserve
or selection policy to manufacture the expected outcome. No model inference is
needed to establish these mechanical facts.

Then declare the next useful job from the actual closed result. Preserve complete
ledger delivery, accounts, sources, edits and old outcomes as history. If opportunity
was exhausted, a successor must explicitly state its new finite opportunity and
inheritance; do not reclassify it as a completed original attempt. Count the entire
lineage. The later distinct E18 observation entry remains the next fresh workload,
with no forced source group, account, recovery or new memory architecture.

These corrections are supported operational descriptions, not a demonstrated
speedup or a guarantee that the actor will finish a future operation. Whole-work
quality, actual evidence use, termination and all costs remain evaluation targets.
