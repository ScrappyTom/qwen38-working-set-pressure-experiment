Extend the saved configparser with opt-in unnamed-section support. This is a new
feature job on the previously completed parser, not a full upstream version upgrade.

Add keyword-only allow_unnamed_section=False to both parser constructors. Export
UNNAMED_SECTION, a distinct non-string section sentinel, and
UnnamedSectionDisabledError, a subclass of Error. With the feature disabled,
headerless option input must still raise MissingSectionHeaderError; explicitly
adding the sentinel section must raise UnnamedSectionDisabledError.

With the feature enabled, options before the first section header belong to
UNNAMED_SECTION, separately from defaults and named sections. Support read_string,
read_file and normal multi-source merging. Comments/blank lines, option name
transformation, strict duplicate checks, continuation and allow_no_value behavior
must remain consistent with existing sections. Empty/comment-only input and input
beginning with an ordinary section need not create an unused unnamed section.

Support the sentinel through add_section, get/set, section-proxy access, read_dict,
and parser[UNNAMED_SECTION] = mapping. Dictionary input must preserve the sentinel
identity rather than convert it to a named string section. Mapping replacement must
replace that section's own options as for ordinary sections. Preserve defaults,
interpolation and converters; unnamed options must not become defaults inherited
by named sections. The ordinary non-string conversion rules for read_dict remain.

write() must emit nonempty unnamed options without a section header and before
all headers, including the default-section header. Reading that output with the
feature enabled must preserve the distinct unnamed, default and named values,
including with a customized default-section name. An empty unnamed section emits
nothing. Preserve delimiters, valueless options and existing formatting for named
sections. The saved InvalidWriteError key protections must apply to unnamed
options too. Do not weaken the existing multiline-continuation repair. No atomic
write guarantee or universal serialization of arbitrary objects is requested.

Implement in Lib/configparser.py. Add meaningful public-API unittest regressions
in Lib/test/test_configparser_unnamed.py and document the feature, disabled default,
sentinel, error and a short usage example in Doc/library/configparser.rst. Keep all
previous test files, support/data and license files byte-identical. Preserve the
earlier documentation's accurate descriptions of multiline and write safety.

The public check runs all preserved parser tests, independent feature/integration
cases and your new tests on the current library. It also runs the new tests against
the saved library without this feature: expected comparison failures/errors show
baseline incompatibility, not failure of the current library. Missing-API errors
alone do not establish good test coverage; assertion quality and behavioral
sensitivity are separately reviewed. Documentation declarations are checked
mechanically, with prose/examples reviewed independently.

Begin with no selected sources or account. Acquire what you need, save the feature,
consume an actual current public check and submit. There is no full-file reading
quota, required account update, forced failure or required selection sequence.
