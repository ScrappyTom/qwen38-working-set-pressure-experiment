# Continuation replay boundary

`verify_run.py` is an evaluator-only successor to the original URL replay helper. The original helper and run are unchanged. The continuation helper has been syntax-checked; it must not be executed against an open run. A complete run inventory and `RESPONSE_SEAL.json` are prerequisites. Qualification and replay remain separate from direct transcript and artifact review.

The inherited boundary is the exact sealed URL run 002: twenty consumed model requests, thirty archived operations, candidate `83d8704c0a98ca6b201c991c56951d2e95bc060af33523531aa0b7789bf304ef`, and the executed failed tests observation `CHK-0030`. The helper validates the original seal/inventory/custody and exact replay proof. It checks that the initial snapshot equals the original final snapshot with only `request_limit` changed from 20 to 36. Source versions, selection, recovery inspections, account-containing operation history, preceding receipts and candidate remain exact. The copied raw observation must match all four original observation files byte for byte.

The first prospective request is checked twice: against its sealed preparation wire and against the original admitted final feedback input. Only the two request-allowance fields may differ. System text, grammar, sampling/runtime envelope, source, task, accounts and earlier receipts remain unchanged. The actual failed criterion must be `detect.error_class` with normal control passing. No corrected assertion, evaluator source group, prior private thinking or new factual guidance may appear. Decoder reuse is bound to the actual unchanged grammar and the published original native-form proof.

New request IDs begin at C21. The helper never replaces the cumulative session counter with the local number of continuation dispatches. It verifies inherited counts 20/30, cumulative limits 36/60, the controller's start/close accounting records, cumulative task-loop totals, and the response seal's separately named new dispatch and operation totals. The original `starting_archive_length` remains zero; the original thirty operation pairs must remain intact while new operations append.

The rest of replay retains the original strong boundaries: saved template/token requests, native text/count/wire identities, public-final decoding, exact receipts, operation ordering, every actual checkpoint and candidate version, numeric diff addresses, unchanged incoming restore objects, check scope/candidate/definition applicability, preserved stream bytes, complete closure and submission eligibility. Replay imports recorded observations and native measurements. `subprocess.Popen` in the observation executor is prohibited; no model, checker, tokenization or server launch is permitted.

Inherited `CHK-0030` is verified separately from newly recorded check callbacks. Its historical failure stays a historical failure even if a later successor passes. Unfinished reasoning, empty or malformed public finals, transport stops and reply-processing stops remain inert; they cannot be promoted into executable work. Failed verification writes a separate failure artifact, and an existing differing result must not be overwritten. An initialization failure before a starting checkpoint is not a completed model trajectory and cannot receive `replayed_exactly` from this helper; its failure custody and closure must be audited separately.

`measure_run.py` is also post-closure only. It requires exact replay first and independently reads the old and new saved endpoint usages, wire counters, receipts and sizing trials. It reports inherited, new and cumulative cost separately, preserves unknown generation/timing rather than estimating, and keeps native sizing maxima distinct from sent input maxima. It performs no host or observation execution. The final prepared receipt is explicitly distinct from feedback received by another adaptive request.

Neither helper evaluates account truth, meaningful coverage, documentation accuracy, evidence interpretation, account benefit or general autonomous capability. A checked continuation would establish completion from saved work under declared additional opportunity; it would not rewrite the original exhausted attempt as success within twenty requests.
