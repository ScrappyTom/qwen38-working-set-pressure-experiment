## Native rehearsal requirements

The native result must record every criterion named by NATIVE_CRITERIA in
execution_task.py, its actual input/output evidence and the unchanged starting
candidate/checker/actor/limits. A complete checked contribution is researcher-
scripted host feasibility, never a model result. For each choice identify the
support actually present; reference edits stay evaluator-side.

- **File-size and snapshots:** the legacy ten-file snapshot omits max_file_bytes.
  The entry explicitly reinstates 1,048,576 bytes, and every new saved candidate
  must serialize that value. Reconstruct after edits without reverting to the
  historical default. Exercise actual large library/test/document reads.
- **Discovery and exact edits:** obtain reusable locations through real tree,
  search or outline replies; deliver exact current text; save a bounded library,
  regression and documentation contribution; inspect refreshed source and the
  actual applied diff. Keep its complete RES recovery available after omission.
- **Observation/report:** inspect existing meaningful failures in immediate and
  standing views under native sizing, then execute actual failed and passing
  checks on the current candidate. Keep the original-parser comparison separate
  from current failure. Incomplete capture remains explicit. Exact diagnostic
  recovery and subsequent correction must reach the following actual input.
- **Broad selection:** exercise large ordinary acquisition and a real capacity
  obstacle or deliberate supported rejection, then a model-expressible narrower
  selection. Immediate feedback and current account/bindings must remain usable.
  Do not substitute only a compact evaluator-selected route for this boundary.
- **Decoder and closure:** retain the exact reused public-only decoder proof for
  JSON edit, literal SOURCE edit, account plus operation and explicit public check,
  including rejection of check_after and unavailable scopes. Verify the actual
  new task's requests still carry that grammar and open-thinking template controls;
  qualify the edit-to-explicit-check-to-submission journey. Rerun decoder cases only
  if these inputs or runtime identities differ. No whole-response cap, private-draft
  execution or server-side repair is introduced.

The native gate is intentionally absent now. A Boolean summary alone is not a
review: inspect the source-bound captured requests, decoded forms, checker results
and final artifact before marking those criteria passed. Documentation accuracy
and preexisting-test preservation remain independently reviewed obligations even
after the original public check passes.
