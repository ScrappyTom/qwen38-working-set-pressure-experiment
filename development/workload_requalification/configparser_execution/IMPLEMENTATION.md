# Offline execution-adapter readiness

22 September 2026. The thin adapter is implemented and CPU-qualified. No server,
native tokenizer/renderer, model or checker subprocess ran for this package.
`configparser_original` and all prior evidence are unchanged. This is not a live
freeze or a demonstrated completion of the original backport.

## Implemented boundary

`execution_task.py` loads the original ten-file candidate and exact task through
the frozen CPU adapter, then opts into `NavigationMixin`. Its original task-specific
report API and incident/session annotation remain. Initial source selection, saved
results, account, history, checks and inherited operations are empty. File admission
is explicitly 1,048,576 bytes. The checked instrumented checker is byte-identical
to CPU qualification 005; its original acceptance algorithm is unchanged.

The adapter exposes one public check, optional account, ordinary JSON and literal
SOURCE forms. There is no automatic check or check_after field. Request and
operation accounting are separately fixed at 40 and 80, with medium uncapped
thinking, q4_0 K/V, no MTP, 56,576 physical context, 23,808 input ceiling and seed
961221. `run_configparser.py` reuses the existing monitored uncoached lifecycle.
Its prepare mode renders only the actual initial empty state after the larger
information-path qualification passes; it does not run a tiny-task reference
fragment or borrow the small-repair script's hardcoded 24/72 limits.

`bootstrap.py` lists existing import directories explicitly so the adapter and
tests run without an undocumented shell PYTHONPATH. Importing these modules does
not invoke their command-line execution paths. `Task` rejects nonnumeric or
path-containing version names; existing preparation/run directories remain
nonreusable under the common lifecycle.

## Qualification custody

The CPU prerequisite binds all 196 seal/output entries from checker-qualification-
005, requires its current complete source closure and successful CPU-only status,
and checks the seven acceptance outcomes, unexpected-success diagnostic and nine
capture/report boundaries. Path traversal, duplicate entries, failed status,
changed source and changed sealed outputs are rejected before use.

The exact public-only decoder proof is reused from small_repairs/native-005:
30 bound seal/output entries, identical grammar and reply schema, identical
nonmessage request controls, supported and unsupported form outcomes, and matching
current decoder DLL hashes. This verifies reuse; no vocabulary process or native
call was repeated. The local expected-template computation also retains the pinned
open-thinking envelope. Actual new task rendering and capacity remain unqualified.

`native_bindings()` deliberately requires a future task-specific
native-qualification-001 with current source and CPU/decoder evidence bindings.
It requires the original candidate/checker, actor/limits, zero model completions,
actual native requests, actual checking, and all ten declared information-path
criteria. The criteria are defined in PLAN.md and execution_task.py. The native
decoder criterion can cite the exact reused proof. Review the underlying evidence;
the Boolean criteria alone are not a source/trajectory audit.

Both prepare and run fail before runtime startup if that gate is missing or stale.
The common live verifier additionally binds the preparation seal, every saved
output, the exact initial candidate and wire request, source closure and finite
limits. Root review and prospective publication precede execution.
