# Native rehearsal preparation review

22 September 2026. Source review and CPU-only preflight, before any execution of
this rehearsal. No runtime, tokenizer, checker subprocess or model was invoked by
the implementing reviewer. The existing CPU preparation remains historical.

The runtime adapter preserves the original ten-file candidate, exact task and
acceptance-preserving checker from `configparser_original/checker-qualification-005`.
Its session retains the task-specific report implementation, explicitly sets the
1,048,576-byte file allowance, starts without selected sources or an account, and
uses explicit public checks. The inherited snapshot writer records that file
allowance. CPU prerequisite verification checks the complete source map and sealed
outputs. Decoder reuse checks the actual public-only grammar/schema, nonmessage
request controls, accepted/rejected forms and pinned runtime binary hashes.
Separate read-only review found no blocking integration defect in those paths.

`qualify_native.py` defaults to a preflight that rejects subprocess and endpoint
use. It verified 645 source/prerequisite bindings and reconstructed the exact
previously qualified reference candidate
`490706d83527252b47d6d23a6839a7e707dcc74f2e5b87dd0d90f051e064440f`.
A separate in-memory CPU source/edit smoke check acquired actual search references,
selected exact old source and applied all six reference changes successfully.
Those checks establish neither native input fit nor new checker outcomes.

The parent-scheduled native mode uses the existing owned runtime and request loop
only for rendering and tokenization. It bounds new public executions at two:
the untouched original candidate must fail, and the completed reference must pass.
It preserves raw observations before reading their reports and checks that a real
failure trace reaches immediate feedback and `inspect_check`, that exact outcome
bytes are recoverable, and that the failed assessment remains after later activity.
The later pass must distinguish failed tests against the original parser from
successful tests of the current work.

Broad acquisition requests pages from the real library, test and documentation
files, using actual returned continuation coordinates. It stops that acquisition
sequence on recovery/rejection or after six requests, then delivers a declared
missing-file rejection probe and replaces the selection using a freshly returned
ParsingError reference. This is an engineering transition test. If it never enters
the recovery presentation, the saved evidence must say so; a supported rejection
and successful selection replacement do not prove recovery-mode use.

The six changes are explicitly evaluator-authored proposals, not discoveries or
private model drafts. Each anchor is located through a real current-source search
and delivered before editing. Exception creation additionally acquires Error,
ParsingError and the neighboring three-argument exception; the continuation guard
acquires its enclosing function. Test work obtains existing imports and current
exception/guard source. Documentation work again acquires that actual implementation.
These facts justify applying and checking the known proposal; they do not establish
that Qwen would find it independently. A per-operation decision-path record names
the actual before/after views and distinguishes those two kinds of evidence.

Every saved candidate is reconstructed with its recorded file allowance. Each
visible source extent is compared with current candidate bytes. Edits must display
their actual diff and invalidate the original check's applicability; exact saved
edit retrieval must preserve the candidate. Final source must match the qualified
reference, with the original test text retained. The independent checker and
documentation review retain their original scope limits.

The rehearsal preserves failure output and seals a failed attempt rather than
retrying. Its results count actual native requests and captured check executions
from custody records. No completion request is sent and no model allowance is
consumed. Parent review, actual native execution, output inspection and a separately
frozen initial request still precede live exposure.
