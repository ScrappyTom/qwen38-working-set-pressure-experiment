Let's start by understanding the task. The task is as follows:

1. Extend the configparser implementation with a write-time guard for ambiguous option-name forms
2. Add `InvalidWriteError`, which is a public subclass of `configparser.Error`, exported from the module
3. Both `ConfigParser` and `RawConfigParser` must raise it in the following cases:
   - When writing an option name that starts with the parser's current SECTCRE section pattern
   - When writing an option name that contains any of the delimiter strings configured on that parser
4. Apply this protection to defaults and named sections, including valueless options
5. Use the whole configured delimiter string (including multi-character delimiters)
6. A delimiter that is not configured on that parser is not forbidden
7. The diagnostic message must identify the offending option name
8. Preserve normal write formatting, values, interpolation, valid option names, and the saved multiline continuation repair
9. Implement in `Lib/configparser.py`
10. Add tests in `Lib/test/test_configparser_write_safety.py`
11. Leave existing test modules and support/data/license files byte-identical
12. Update `Doc/library/configparser.rst`

What the check runs:
- The saved existing test suite
- Independent write-safety cases
- My new tests against the current library
- New tests against the saved unsafe write implementation (which is supplied the new exception API)
- At least one assertion must detect unsafe writing there
- The presence of a documentation statement is checked mechanically
