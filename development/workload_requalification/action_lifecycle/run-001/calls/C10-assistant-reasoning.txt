Let me analyze the problem. The task says: "After receipt corrections are imported, the stock report sometimes shows incorrect quantities for depot and item."

Let me look at the code I have:

1. `entries.py` - `contributions(change)` returns entries for a receipt revision transition:
   - If `change.before` is not None and is active, it adds `(change.before, -change.before.units)` — removing the old contribution
   - If `change.after` is active, it adds `(change.after, change.after.units)` — adding the new contribution

2. `totals.py` - `Totals.apply(change)`:
   - `destination = bucket(change.after)` — uses the AFTER receipt's bucket
   - Then for each `(receipt, units)` in `contributions(change)`, it does `self._units[destination] += units`

**HERE'S THE BUG!** In `totals.py`, the `apply` method computes `destination = bucket(change.after)` ONCE, then uses that SAME destination for ALL contributions. But a correction can change the depot or item! So if a correction changes the depot from "A" to "B", the old contribution (negative units for "A") should go to bucket A, and the new contribution should go to bucket B. But the code applies BOTH to the `change.after` bucket (which is B).

So the fix is: in `totals.py`, instead of using a single `destination` for all contributions, use `bucket(receipt)` for each individual receipt in the contributions list.

Let me verify this understanding:
- `contributions(change)` can return up to 2 entries: `(change.before, -units)` and `(change.after, +units)`
- If the correction changes depot/item, these two entries have DIFFERENT buckets
- The bug: `totals.py` uses `bucket(change.after)` for both, so the negative (removing old) is applied to the new bucket instead of the old one

The fix in `totals.py`:
```python
def apply(self, change: Change) -> None:
    for receipt, units in contributions(change):
        destination = bucket(receipt)
        self._units[destination] = self._units.get(destination, 0) + units
        if self._units[destination] == 0:
            del self._units[destination]
```

This way each contribution is applied to its own receipt's bucket.
