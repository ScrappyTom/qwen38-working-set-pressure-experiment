**Bug 1: `_safe_relative_path`**
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The operator precedence here is wrong. Due to Python's operator precedence, `and` binds tighter than `or`, so this is evaluated as:
`(path.is_absolute() and ".." in path.parts) or (not path.parts)`

This means:
- A path like `/etc/passwd` (absolute, no `..`) would NOT be rejected (because `path.is_absolute() and ".." in path.parts` is False, and `not path.parts` is also False)
- A path like `../../etc` (relative with `..`) would NOT be rejected (because `path.is_absolute()` is False, so the first part is False, and `not path.parts` is False)

The correct behavior should be: reject if the path is absolute, OR if `..` is in parts, OR if parts is empty.

So the fix should be:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() or ".." in path.parts or not path.parts:
        return None
    return path
```

**Bug 2: `_bounded_timeout`**
```python
def _bounded_timeout(value) -> int:
    try:
        timeout = int(value)
    except (TypeError, ValueError):
        timeout = 20
    return max(1, max(timeout, MAX_COMMAND_TIMEOUT_SECONDS))
```

The problem: `max(timeout, MAX_COMMAND_TIMEOUT_SECONDS)` means if timeout < 60, it returns 60. The correct clamp should be:
- If timeout < 1, use 1
- If timeout > MAX_COMMAND_TIMEOUT_SECONDS (60), use 60
- Otherwise use timeout

So the fix should be:
```python
def _bounded_timeout(value) -> int:
    try:
        timeout = int(value)
    except (TypeError, ValueError):
        timeout = 20
    return min(MAX_COMMAND_TIMEOUT_SECONDS, max(1, timeout))
```
