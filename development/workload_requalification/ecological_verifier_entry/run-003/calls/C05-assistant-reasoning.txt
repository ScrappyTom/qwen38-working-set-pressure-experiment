1. `_safe_relative_path`: The current implementation is:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The problem: The operator precedence is wrong. `path.is_absolute() and ".." in path.parts or not path.parts` is parsed as `(path.is_absolute() and ".." in path.parts) or (not path.parts)`. So:
- It only rejects absolute paths IF they also contain ".." - a plain absolute path like `/etc/passwd` would NOT be rejected.
- It only rejects parent traversal if the path is absolute - a relative path like `../../etc/passwd` would NOT be rejected.
- Empty paths are rejected (not path.parts is True for empty).

The fix should be: reject if absolute, OR if contains ".." as a part, OR if empty.

```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if not path.parts or path.is_absolute() or ".." in path.parts:
        return None
    return path
```

2. `_bounded_timeout`: The current implementation is:
```python
def _bounded_timeout(value) -> int:
    try:
        timeout = int(value)
    except (TypeError, ValueError):
        timeout = 20
    return max(1, max(timeout, MAX_COMMAND_TIMEOUT_SECONDS))
```

The problem: `max(1, max(timeout, MAX_COMMAND_TIMEOUT_SECONDS))` - this clamps to [MAX_COMMAND_TIMEOUT_SECONDS, infinity) when timeout > 1, or [1, MAX_COMMAND_TIMEOUT_SECONDS] only if timeout < 1. Actually let me think again:
- If timeout = 5: max(5, 60) = 60, max(1, 60) = 60. So it returns 60.
- If timeout = 100: max(100, 60) = 100, max(1, 100) = 100. So it returns 100 (above max!).
- If timeout = 0: max(0, 60) = 60, max(1, 60) = 60. Returns 60.
- If timeout = -5: max(-5, 60) = 60, max(1, 60) = 60. Returns 60.
- If timeout = 30: max(30, 60) = 60, max(1, 60) = 60. Returns 60.

Wait that's wrong. The behavior should be: clamp to [1, MAX_COMMAND_TIMEOUT_SECONDS]. So:
- If timeout < 1, return 1
- If timeout > MAX_COMMAND_TIMEOUT_SECONDS (60), return 60
- Otherwise return timeout
- Invalid values default to 20

The current code `max(1, max(timeout, MAX_COMMAND_TIMEOUT_SECONDS))` always returns at least MAX_COMMAND_TIMEOUT_SECONDS (60). So a valid timeout of 30 gets clamped to 60, and a timeout of 100 stays at 100 (exceeds max).

The fix should be:
```python
def _bounded_timeout(value) -> int:
    try:
        timeout = int(value)
    except (TypeError, ValueError):
        timeout = 20
    return max(1, min(timeout, MAX_COMMAND_TIMEOUT_SECONDS))
```

This clamps to [1, 60]:
- timeout=5 → min(5,60)=5, max(1,5)=5 ✓
- timeout=100 → min(100,60)=60, max(1,60)=60 ✓
- timeout=0 → min(0,60)=0, max(1,0)=1 ✓
- timeout=-5 → min(-5,60)=-5, max(1,-5)=1 ✓
- invalid → timeout=20, min(20,60)=20, max(1,20)=20 ✓
