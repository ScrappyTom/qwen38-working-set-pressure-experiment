## What responsibility is missing

The exact edit guard answers whether the proposed old text is eligible to be
changed. It does not answer whether the task's pre-edit prerequisites have been
met. Checker applicability similarly answers which execution applies; its empty
`verification.outstanding` list is not a claim that every task obligation is met.

The host currently holds the task as text while enforcing a different set of
mechanical conditions. An optional account can preserve an unfinished obligation,
but it cannot reliably supply host-derived prerequisite state. Here the model
recognized the prerequisite twice before it ceased to affect the next operation.
This earns consideration of a small task-policy boundary rather than another
generic reminder or an unchanged repeat. It does not establish that a reminder
could never help, or that the account caused the omission.

## Recommended minimum policy

For a separately declared follow-on configuration, register these four paths as
task-local prerequisites for the first accepted file mutation. Obtain the paths
from the explicit assignment, with the owner-approved configuration bound in the
preparation. Do not introduce a universal parser that silently interprets arbitrary
task prose, dependencies or semantic inspection requirements.

The minimal mechanical condition is **some nonempty exact current-source exposure
for every named path, before mutation**. Call it exposure, not completed inspection.
Record the actual ranges rather than claiming that the whole path was read.
This is a necessary condition that prevents the wholly omitted paths observed
here. It deliberately does not assert that a one-line excerpt, docstring or full
file was understood, that the selected range was relevant, or that the task was
substantively satisfied. Those judgments remain independently reviewed.

E19 does not justify requiring every line or inventing a byte percentage, minimum
token count, or semantic importance threshold. If complete-file exposure is desired,
declare that stronger prospective policy explicitly; do not present it as the
unchanged E19 requirement. E20's explicit every-line rule warrants different
mechanical coverage semantics when that entry is prepared.

For this minimal policy:

- Credit only source bytes in an actual admitted and sent model input, validated
  against the current path, file fingerprint, exact line extent and content. A
  requested read, archived but undelivered acquisition, outline, search address,
  account, imported observation or recovery inventory is insufficient. A complete
  historical source result can count only after the existing source validator has
  established exact unchanged current bytes; serialized prefixes cannot count.
- Track historical exposure separately from the current edit-eligibility view.
  The existing `delivered_sources` is replaced for each call, so it is not by
  itself a cumulative prerequisite record. Releasing a displayed body should not
  erase a genuine earlier exposure of the unchanged file. A changed file identity
  invalidates its earlier credit. Empty or out-of-range views of these nonempty
  files do not qualify; any future empty-file rule must establish actual EOF.
- Render a bounded four-path inventory with missing paths and observed extents.
  Label it as a task-policy condition, separate from checks and model-authored
  accounts. Preserve its source-call witnesses, policy identity and first-mutation
  boundary in snapshots/replay. The host can derive these facts mechanically; it
  must not derive an assertion of comprehension from them.
- Check both guarded patch forms at the mutation boundary. If prerequisites are
  missing, preserve the public proposal and reject its mutation with the exact
  missing paths and supported acquisition forms. No source change, successor check
  or automatic source acquisition follows. Keep account handling and operation
  charging explicit; do not silently change those rules as part of this guard.
- Once the first mutation is admitted, retain the exposure record and temporal
  audit. This task says before mutation, not before every later edit. Continue to
  enforce ordinary exact-source guards, actual check applicability and submission
  requirements independently.

The model still chooses relevant ranges, ordering, evidence groups, diagnosis and
work. The host can prevent a mechanically impossible claim of pre-edit exposure
without becoming the judge of which code establishes the repair. No blanket
retention, automatic checker, extra model, mandatory account or claim graph is
needed for this responsibility.

## Qualification and limits

Preserve run-002 and its old replay unchanged. In a separately labeled engineering
counterfactual, the actual C03 proposal should be rejected under the new policy
because the other three paths lack delivered source. This must not be reported as
the historical host's behavior or as proof Qwen would recover.

Qualify actual sent-input coverage, absent and partial ranges, wrong versions,
stored-only and recovery-omitted bodies, explicit release after real exposure,
both edit forms, reconstruction/tampering, and a delivered rejection followed by
model-available acquisition and resubmission. Verify a rejection remains usable
in a crowded view rather than merely calculating that its internal record exists.
Do not supply evaluator-selected ranges in a model attempt or reuse a scripted
semantic decision as evidence that the actor made it.

A future uncoached attempt should report source exposure, substantive inspection,
repair correctness, independent checks, preserved work, completion and total cost
separately. An accepted edit would then partly demonstrate host enforcement. The
actor evidence remains its acquisition choices and use of source, observation and
feedback. If it obtains only trivial excerpts, that is still an unresolved task
quality issue rather than an earned reason to call exposure inspection.

No live coaching or policy change is recommended. Close and review the current
attempt before choosing the follow-on. A focused outside-run test-pilot dialogue
may examine a concrete unsupported transition if one remains; it need not be a
prerequisite to exposing and enforcing these explicit mechanical conditions.
