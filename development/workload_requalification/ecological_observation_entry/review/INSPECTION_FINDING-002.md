## Existing responsibilities and reusable machinery

The current Task intentionally supplies the required path constant for
qualification/audit, without an acceptance gate. Its published plan says not to
silently add a four-file gate or E20's stronger every-line requirement. Acceptance
therefore follows the selected baseline; this is an exposed responsibility gap,
not an unexpected violation of an already implemented gate.

`DecisionSession.mark_delivered` validates the actual view and records exact
current source bodies. `_verified_source_ranges` checks actual bytes, bounds and
file identity. The edit path uses those bodies to protect the changed target.
These are the useful enforcement boundary and validator; an accepted read result
alone is not proof that its source reached a later model input.

Legacy `ToolExecutor.required_full_reads` is not the missing edit guard. Its
`complete_reads` is credited during acquisition, and the requirement is consulted
by fork_ready rather than patch. Merely passing the four paths to that constructor
would neither enforce pre-mutation inspection here nor establish delivery.

E20's `ecological_pilot_v2.inspection_status` supplies useful coverage rules:
exact version/bytes, continuous union of adjacent pages, no credit for a lone EOF
page or empty beyond-EOF request, and freeze at first accepted mutation. It is an
audit of old read-result shapes, not a current decision-interface gate. It only
recognizes patch, and does not consume today's nested read receipts, grouped
acquisitions or actual sent views. Reusing its principles is justified; importing
it unchanged would miss these boundaries.
