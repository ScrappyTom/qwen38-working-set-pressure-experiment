## Bounded implementation

1. Add one opt-in, model-authored contribution selection operation to the existing
   host. It records a local objective and an optional existing check scope. It
   selects no source, grants no editing authority, supplies no diagnosis, and
   never asserts completion. Ordinary operations remain available without it.
   The existing account continues to hold reasoning and unresolved questions.
2. Present that objective with mechanically derived changed paths and the actual
   applicability of its selected check. Keep the whole task and current source
   available. Changing/clearing the objective changes neither work nor evidence.
   Recovering an old selection does not make it current. Store it in the ordinary
   operation archive; introduce no parallel account store.
3. Add an opt-in runner adapter with declared per-request and total elapsed
   budgets, plus an elapsed limit on edited work awaiting an applicable check.
   An actual failed check counts as an observation, not a successful contribution.
   Objective/account changes do not reset any budget. A deadline stops the
   attempt, preserves incomplete transport and committed work, and never extracts
   an action from private thinking. No automatic retry or budget extension.
4. Require a small experiment contract: one question and changed variable,
   held-fixed settings, exact saved-state fixtures, information-path review,
   success/failure criteria, costs, and the decision each outcome would justify.
   These are evaluator records; do not feed reference decisions to the actor.

This is a declared development package, not evidence isolating each component.

## Qualification and decisions

Mechanical tests must cover selection/change/clear/history, source authority,
failed-check correction, candidate and checker changes, capacity rejection,
snapshot restoration, and one completed code contribution through real CPU checks.
Runner tests must cover normal closure, between-call limits, an in-flight deadline,
partial response preservation, no effect from incomplete output, and budget
persistence despite account/focus updates. Preserve historical default behavior.

Saved-state fixtures cover (a) visible source with expensive small edits in the
unnamed task, (b) actual failed-check recovery in dispatch work, and (c) continuation
after source release. For every scripted decision, identify the exact input that
supports it and any evaluator-supplied choice. Inspect the complete proposed
inputs. CPU byte counts and mock tokenizers are not native admission qualification.

CPU success permits a separately prepared native-format/capacity qualification;
it does not authorize or establish a model run. Before future inference, bind the
actual template, grammar, source/checker identities, sampler and finite budgets.
Before fresh full-task work, require a completed bounded contribution and direct
review. Keep correctness, preservation, actual evidence use, termination, total
cost and review effort separate. Retain the interface if no benefit is shown.
