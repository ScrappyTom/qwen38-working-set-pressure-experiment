# Original case adapters

The new Task parameterizes the original E14 bank, case identity, file count, named
check scopes and phase/probe session. It reuses the existing host for all acquisition,
guarded edits, accounts, checks, result capture, recovery and submission. There is
no new store, selection policy, reasoning setting or semantic account mechanism.
Existing phase/probe code and historical evidence are unchanged.

MINT uses the same authored-fixture probe and archive-derived OBS aliases as ANCHOR.
SABLE uses the source-only phase session. It does not acquire a probe requirement or
capability. Scope text is attached to each exact checker contract and derived report;
it cannot turn SABLE's invariant-only public pass into evidence of name correctness.
The full and paged reports use the same scoped explanation, and raw observations
remain preserved by the existing capture path.

Restoration checks the actual serialized shape, version history, diffs, delivered
coverage, opportunity and case. It retains the normalized JSON diff keys qualified
for ANCHOR. Every scripted checkpoint is read through serialization before restore;
in-memory reconstruction alone is insufficient. Branch-local probe identity remains
derived from each ordinary archive.

reply routes with every serialized checkpoint, altered diffs and opportunity, mixed
case rejection, scope truth, supported operations and independent probe branches.
The SABLE scope test deliberately demonstrates its original public pass on the
unrepaired name function. This is a checker-scope qualification, not actor success.
Test API signatures were checked against the source before execution; no production
change was made to satisfy a mistaken test expectation.

The run controller and native matcher are the existing ones, selected per case.
Native preparation still must qualify complete and crowded information paths and
all supported reply forms, replay them, and receive direct initial-input review.
No Qwen completion has been executed for these new entries at this implementation
stage. Post-run scripts are explicitly separate evaluator code and record their own
provenance. They neither change bound actor code nor enter its input.
