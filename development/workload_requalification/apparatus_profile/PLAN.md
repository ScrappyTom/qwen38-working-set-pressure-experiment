# Follow-through earned by measured validation cost

Closed-run timing isolates approximately ten seconds per complete source-closure
verification. The exception-transport broad-read qualification then repeats that
verification for each internal page-sizing trial, while native tokenization itself
was approximately1.4 seconds over54 earlier calls. The long-term apparatus needs
a defined validation boundary, not only a higher worker count.

After the currently frozen qualification, evaluate one opt-in arrangement that
retains full validation before model dispatch and before executing its response,
and validates a complete internal sizing/transition batch rather than every tentative
page. Keep all exact native inputs, counts, receipts and final closure verification.
No timestamp cache, unverified dispatch, altered model setting or evidence rewriting.
Historical and active-source roles must be explicit if their validation differs.

Before adoption, enumerate actual dynamic file reads and every source-check caller.
Test source changes before dispatch, during a sizing batch, after a response and at
closure; preserve already executed effects on a late integrity failure. Compare
admitted input bytes, action results and mutation detection at the declared boundaries
against the existing runner. Report any loss in earlier detection as a policy change,
not an allegedly neutral optimization. Do not weaken integrity merely to reduce the
profile's timing. No active run or qualification uses this proposed arrangement.
