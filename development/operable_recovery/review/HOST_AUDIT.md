The implementation frozen at 70e6e21ce7d2a24c593477b51dfda300610b4780 is an
opt-in successor. Historical configurations, original evidence and their consumed

## Preservation before presentation

The new check path preserves its outcome and captured raw streams before report
formatting and custody-records them at that boundary. The task checker no longer
discards its detailed structured failures before this capture. Primary real failures
take precedence over optional injected-fault traces in the small displayed report.
CHK inspection returns exact captured pages under the recorded candidate, checker
and scope. A completed check remains executed if later report construction fails.

Storage is finite: one MiB per stream, 128 MiB per attempt and thirty seconds per
check. Capture termination and timeout are explicit incomplete observations; they
cannot pass. Insufficient storage rejects before execution. These are guarantees
about captured observations, not promises that uncaptured output can be recovered.

CPU/native qualification exercised long and quote-heavy output, exact paged
reconstruction, failed-check correction, multiple immediate receipts and report
fallback. Five actual reference-route observations replay from preserved files
without re-execution. The native correction input contains the real expected/actual
message mismatch before the scripted account attributes its revision to that check.
This corrects the previous information-path error; it remains researcher-scripted
feasibility rather than autonomous Qwen correction.

The live C11 edit triggers an actual tests check on its saved successor. Its
8,402 stdout bytes are preserved completely, including bytes beyond the old
8,192-byte capture boundary. C12 requests CHK-0020 stdout and receives its first
4,096 exact bytes, with total length and continuation. The next native input is
19,871 tokens and retains selected source. The check remains accepted execution
with `passed=false`; no historical wrapper rejects or relabels it.

The ordinary suites pass, but the new test misses exact-class fault sensitivity.
The initial report says six of seven injected faults were detected, without naming
the escaping fault. The acquired page contains its complete `error_class` entry.
Thus the necessary detail is recoverable and delivered. Naming unmet check criteria
in the initial report is a possible further report improvement; it is distinct from
preservation and should not be described as a missing or destroyed observation here.

## A remaining presentation cost

Recovery currently displays at most 512 bytes of the account at its first control
tier, even when the complete small account would fit comfortably. C04 receives
that labelled prefix beside a 5,761-token input, notices a cut diagnostic and
reacquires implementation. It copies the shortened snippet into its next account.
The original complete account and acquired source remain archived; this is a
presentation limitation, not storage corruption or a false claim of completeness.

The temporary implementation page had also included both `_hostinfo` paths. Their
conclusion was not saved before another inspection replaced the temporary page.
Later ordinary selection retains the accessor but not those paths. These combine
two different issues: the host unnecessarily shortens a small account, and the
model does not carry the available dependency evidence or derive and record its
empty-port consequence before changing what it inspects. C03 names the host-info
properties but does not explicitly derive that consequence; this is not proof of
a correct conclusion being forgotten. The later unsupported assumption cannot be attributed
only to either one. It is corrected when both paths are acquired again.

Do not silently modify this frozen run. A prospective control view should distinguish
the maximum supported account size from how much of a small current account it can
afford to display. This does not earn mandatory accounts, automatic semantic
summaries, or a claim that full account display would ensure completed work.

## Limits of qualification

Ninety-four selected checks and eleven native grammar cases support the declared
paths; they are not a full repository suite or a reliability rate. Supported-size
control trials include a 780,000-byte account, long errors and 400 designations.
They establish a bounded control input and a subsequent selection transition, not
that every possible semantic problem has a good selection or that Qwen will choose
one. Medium uncapped reasoning remains a separate action-completion risk.

## Closed live path and remaining boundaries

All sixteen executed results reach the following input exactly. Delivered current
source matches its candidate, file fingerprint and stated range. Twelve complete
replies replay exactly; C13's empty final causes no operation. The last saved
candidate survives closure unchanged. No new mechanical custody, edit, delivery
or execution-status defect is established on this live path.

C13 does establish a report-interpretation problem. Its input contains the entire
`error_class` record, yet it calls that mutation run's success good and tries to
repair expected failures from other mutations. A test-run `successful` field has
one meaning for ordinary execution and an opposite implication for injected-fault
detection. The normal path-completeness requirement is also repeatedly transferred
to mutation runs where it is not a criterion. Correct stored fields have not made
these assessment scopes operationally clear.

A future derived report should name unmet criteria and undetected faults, and
explain detection separately from the raw test-run outcome. That is a source-derived
reporting responsibility; it need not invent the repair or expose a reference test.
Raw observations should remain exact and accessible. This proposed correction is
not implemented inside or after the frozen attempt in this package.

The final account remains the pre-acquisition C09 revision. It has accurate accessor
rules but stale pending-work text; no automatic host rewrite occurs. Its provenance
does not certify current relevance or evidential support. Neither full account
display nor clearer reporting has yet been tested as a behavioral remedy here.

The new recovery mode is exercised; complete exact-region assembly is not. The
check boundary is exercised through a failed quality check and exact inspection;
model correction is not. A new proposal channel is deliberately outside this
configuration, and extracting unfinished thinking would not be an equivalent test.
The combined system still needs a reliable passage from an interpreted observation
to a completed next decision. No increase in unused request allowance is justified
by this context-exhausted response alone.
