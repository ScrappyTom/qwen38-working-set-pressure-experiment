Handling Missing Interpolation References
------------------------------------------

If a value references an option that does not exist, calling
:meth:`ConfigParser.get` raises :exc:`InterpolationMissingOptionError`.
This can happen in both :class:`BasicInterpolation` and
:class:`ExtendedInterpolation` modes.

.. doctest::

   >>> import configparser
   >>> c = configparser.ConfigParser(
   ...     interpolation=configparser.BasicInterpolation())
   >>> c.read_string("[sect]\nname = %(missing)s\n")
   >>> try:
   ...     c.get("sect", "name")
   ... except configparser.InterpolationMissingOptionError as e:
   ...     print(e.option)
   ...     print(e.section)
   ...     print(e.reference)
   name
   sect
   missing

The exception carries the *option* that was being resolved, the
*section* it belongs to, the *reference* that was not found, and the
*raw value* (the unresolved string exactly as stored in the file).

.. doctest::

   >>> raw = c.get("sect", "name", raw=True)
   >>> print(raw)
   %(missing)s

Using ``raw=True`` skips interpolation entirely and returns the
unresolved text, which is useful for inspecting or repairing the
configuration without triggering the error.

Once the missing option is supplied, the lookup succeeds:

.. doctest::

   >>> c.set("sect", "missing", "provided")
   >>> print(c.get("sect", "name"))
   provided

The same applies to :class:`ExtendedInterpolation`.  A same-section
reference and a cross-section reference each raise the error when the
target is absent:

.. doctest::

   >>> ce = configparser.ConfigParser(
   ...     interpolation=configparser.ExtendedInterpolation())
   >>> ce.read_string("[sect]\nname = ${missing}/path\n")
   >>> try:
   ...     ce.get("sect", "name")
   ... except configparser.InterpolationMissingOptionError as e:
   ...     print(e.reference)
   missing

.. doctest::

   >>> ce2 = configparser.ConfigParser(
   ...     interpolation=configparser.ExtendedInterpolation())

   ...     ce2.get("a", "x")
