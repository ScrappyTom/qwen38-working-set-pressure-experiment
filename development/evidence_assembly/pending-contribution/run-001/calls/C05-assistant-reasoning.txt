Missing Interpolation References
-------------------------------

When an interpolated value references an option or section that does not
exist, calling :meth:`~configparser.ConfigParser.get` (without ``raw=True``)
raises :exc:`configparser.InterpolationMissingOptionError`.

.. code-block:: python

    import configparser

    # --- BasicInterpolation ---
    cp = configparser.ConfigParser(
        interpolation=configparser.BasicInterpolation())
    cp.add_section('main')
    cp.set('main', 'value', '42')
    cp.set('main', 'broken', '${undefined_ref}')

    try:
        cp.get('main', 'broken')
    except configparser.InterpolationMissingOptionError as e:
        print(f"{type(e).__name__}: {e}")
        print(f"  missing option: {e.option!r}")
        print(f"  looked-up section: {e.section!r}")

    # raw=True returns the template without attempting resolution
    template = cp.get('main', 'broken', raw=True)
    print(f"raw template: {template!r}")

    # Supply the missing setting so the reference resolves
    cp.set('main', 'undefined_ref', 'filled-in')
    print(f"resolved: {cp.get('main', 'broken')!r}")

    # --- ExtendedInterpolation with a cross-section reference ---
    cp2 = configparser.ConfigParser(
        interpolation=configparser.ExtendedInterpolation())
    cp2.add_section('a')
    cp2.set('a', 'target', 'target-value')
    cp2.add_section('b')
    cp2.set('b', 'broken', '${ghost:nope}')

    try:
        cp2.get('b', 'broken')
    except configparser.InterpolationMissingOptionError as e:
        print(f"{type(e).__name__}: {e}")
        print(f"  missing option: {e.option!r}")
        print(f"  looked-up section: {e.section!r}")

    # raw=True bypasses interpolation entirely
    raw_val = cp2.get('b', 'broken', raw=True)
    print(f"raw template: {raw_val!r}")

    # Provide the missing cross-section reference
    cp2.add_section('ghost')
    cp2.set('ghost', 'nope', 'cross-filled')
    print(f"resolved: {cp2.get('b', 'broken')!r}")

The key differences between the two modes:

* :class:`~configparser.BasicInterpolation` resolves ``${option}`` in the
  same section (falling back to ``DEFAULT``) and ``${section:option}``
  in the named section.

* :class:`~configparser.ExtendedInterpolation` additionally supports
  nested/recursive references and resolves ``${option}`` by walking up
  the section hierarchy before falling back to ``DEFAULT``;
  ``${section:option}`` behaves the same as in basic mode.

In both modes, ``raw=True`` returns the un-interpolated template string
and never raises.  The error is only raised when the parser actually
attempts to resolve the reference.
