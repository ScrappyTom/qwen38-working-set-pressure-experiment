## Need and scope

Directly reviewed evidence includes the actual C04/C05 actions, complete C05 input,
and complete first selection-consultation response. Qwen selected rejection results
while asking for patch proposals, and repeatedly interpreted empty `working_set`
lists beside source in `latest_feedback` as contradictory states. The follow-up
established the actual rendering relationship. An independent native probe showed

known to the original actor or the first consultation answer.

The first change makes the actual input relationship and historical capacity scope
explicit. It does not invent a pending-work designation, select semantic support,
add an account tool, enlarge budgets, alter edit payloads, or claim a performance gain.
The architecture records those open choices so a small clarification cannot be
mistaken for a solution to sustained contribution work.

Place the block in the common reference, not in one frozen task's SYSTEM.txt. Keep
all historical rendered requests and evidence unchanged. Historical verifiers must
use their pinned code; prospective qualification identifies changed source hashes.

## Offline qualification

endpoint is used. Preserve failed qualifications rather than retrying over them.

1. Exercise actual empty, feedback-only, and mixed selection states. Check the
   visible source union, selected saved-record identity, transition to unrelated
   feedback, whole/partial recovery, and exact edit eligibility. The description
   must stay true when feedback is unselected or historical.
2. Check ordinary and contribution requests: one shared explanation, unchanged
   task/state, exact tool schemas and order, and no hidden commentary or assistance.
3. Render/tokenize baseline and revised complete requests on saved C05 and broad
   near-limit states. Save actual request/native bytes and counts. Added text has
   real cost; a newly inadmissible boundary is reported, not padded away or given
   more budget. Preserve 23,808 input / 56,576 physical / 32,768 prospective reserve.
4. Reuse the existing researcher-scripted pending-proposal route: recover proposal
   with source, save the exact edit, retain it through documentation work, consume
   the real check, submit. Run native admission with the revised reference and
   preserve the exact resulting artifact and feedback. This is assisted offline
   feasibility, not a new Qwen trajectory or fresh capability result.
5. Replay the new qualification from its saved inputs/results and verify custody,
   unchanged old evidence, zero completion calls, and runtime closure where used.
   Run focused host/request regressions appropriate to the changed boundary.
