## Opt-in implementation in the existing host

Keep existing source operations, exact archive, version guards, native admission,
history/recovery and ordinary contribution behavior. Introduce an explicitly selected
session/reply policy; historical request forms and behavior remain the defaults.

The model may replace its current working account alongside an ordinary operation,
or update the account alone. The body is concise model-authored text describing
the current question, interpretation, support and unresolved needs. It is not
generated by extracting private thinking. Empty text clears the current account.
The host archives every update with the producing operation/request and input
candidate identity, exposes the current account in subsequent inputs, and retains
exact access to previous versions through existing EVT/RES history.

Account recording precedes any accompanying operation: the model has not received
that operation's result when it authors the account. Store that order explicitly.
If the account is rejected, skip the accompanying operation and deliver the real
rejection. Never silently truncate the account or displace selected evidence to
make it fit. Native whole-input admission owns the size decision. Account updates
consume a recorded operation but require no extra model request when accompanying
an operation. Accounts do not establish source eligibility or a passing check.

Register named check scopes with exact checker definitions. Expose actual latest
results and candidate/definition applicability separately for each scope. Only the
whole-contribution public check can authorize submission. Scope passes are not
interchangeable; a changed definition or candidate does not inherit a pass.

For the declared test/documentation task family, an accepted test-file edit triggers
the test check. An accepted documentation edit triggers the full public check,
including executable examples and preservation/coverage assessment. The examples
check is also available separately. A rejected edit triggers no check. A failed
check preserves the edit. The host binds each check to the real successor and
delivers every actual receipt. No automatic repair, semantic account update or
submission occurs. Show the triggers, scopes and operation costs in the input.

Reserve operation allowance for the complete declared reply sequence before starting
it. A reply can record an account, execute one requested operation and perform its
declared check; it cannot execute an arbitrary adaptive action list. The existing
request ceiling and accounting remain independently visible. Preserve actual
execution even if subsequent delivery fails, and stop before an input lacking
required immediate feedback is sent.
