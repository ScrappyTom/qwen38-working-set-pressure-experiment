## Eligibility of the visible excerpt and of fully recovered historical source

**Visible current-source excerpt.** Yes, it supplies eligible old text. The corrected contract is explicit: "exact old text contained in a visible current-source excerpt" is sufficient; the whole file need not be shown, and no separate complete historical result is required. The state excerpt shows the anchor fragment in `Lib/test/test_urlparse.py` (lines 1–800, fingerprint `c8f4d478…`) already in the working set. That is the current-source route. It is closed. No further `read` or `work_on` is needed to establish `old`-text visibility.

**Fully recovered historical source.** Yes, it can qualify, but through a separate route and under its own condition. A saved read/group result recovered *completely* (for example, `reopen_result` at offset 0 that returns all saved bytes in one page) qualifies if its source bytes and file fingerprint still match the current file. The disqualifier is a *partial serialized result*—a page that is a strict subset of the saved blob—delivered through that historical route. `reopen_result` does not inherently return a partial result; the offset and returned extent determine completeness. A single-page recovery at offset 0 is complete.

These are two independent routes to the same gate: the host must be able to verify that `old` matches the current file. The current-source route is already satisfied here. The historical route is available but not needed.

## Misleading operational consequence

One framing risk is worth naming, not to justify a change but because it affects how the model reads the rejection:

The frame says "the latest source acquisition was rejected for input capacity." This phrasing locates the problem in the *acquisition*—the specific `read` of lines 800–900. A model that fixes on that reading may conclude "I must read a narrower range of the test file" and issue another `read` (say, lines 800–850), only to be rejected again because the working set is still too large to accommodate any additional source. The corrected contract makes clear the measurement is on the **complete next input**: refreshed selected source, operation receipts, candidate limits, fragment and action byte sizes. The working set holds three broad selections (rst 1–39, test 1–800, parse.py 1–648) plus archive overhead. The rejection is a property of that configuration, not of the particular line range requested.

The frame does not *introduce* this misreading—the system message and the corrected contract both state the complete-next-input measurement—but it does not *correct* it either, because it uses the same "source acquisition … rejected for input capacity" phrasing. A model that reads the frame without also reading the contract's capacity clause will see a problem with the read and not with the working set.

This is the one operational consequence that could misdirect a next operation: choosing a smaller `read` range instead of a `work_on` that reconfigures the working set to a tighter group. The corrected contract already addresses this. No change to the frame is required; the model needs the contract in view, which it has.
