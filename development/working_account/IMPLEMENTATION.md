# Authored understanding and observed verification

The owner approved the plan published at a904ef9e. This implementation is opt-in
in the existing host; the historical ordinary contribution protocol remains the
default. No archive migration, private-thinking extraction, in-run coaching or
automatic semantic endorsement is introduced.

`AccountedSession` derives the current working account from the latest accepted
`record_account` event. Every revision and clear remains in the exact EVT/RES
archive. The input contains one current account with author role, producing event,
request and input-candidate provenance. Its text is not silently revised after an
edit or a check. Source selection can change without losing that account or the
saved artifact. Accounts cannot satisfy exact-source edit eligibility or checked
submission. Earlier discussion and thinking still are not carried into later inputs.

An ordinary reply can include the account and one operation. The host records the
account first, since the model has not seen the operation's result. A rejected
account skips its associated operation. The complete proposed input is measured;
oversized accounts are rejected without truncation, release of selected source,
or replacement of the previous current account. Discussion alone ends the run;
account alone records an update and continues. All offered wrapper forms are now
explicit in the model-facing contract as well as the decoder schema.

The task registers named checker definitions and an exact path-to-check rule.
An accepted test edit triggers tests; a documentation edit triggers public. The
host reserves the required operation allowance, binds the check to the real saved
successor and records account, edit and check separately. Rejected edits skip the
check; failed checks preserve edits. Every receipt is supplied before the next
decision. Execution remains recorded if later delivery cannot fit; the loop stops
before asking the model to act without required immediate feedback. Only a current
public pass authorizes submission. A tests or examples pass carries its actual
scope and cannot authorize completion.

The host's role is execution and applicability, not adjudicating the account's
claims. A model can still omit an uncertainty, preserve a wrong explanation or
ignore a failing result. The new task evaluation must examine those decisions,
not merely count accepted operations. Automatic checking is a declared part of
the system being evaluated, so checked submissions are partly a host guarantee.

The shared runner and replay verifier now ask the task adapter for its selected
reply schema and reply-processing policy. Default adapters retain the previous
protocol. The ordinary working session has two narrow extension hooks for action
validation and full mutation admission. The account/check implementation remains
separate from the legacy default.

The first 54 selected checks passed. After the complete contract and integrations,
96 selected checks pass in `tests-001.txt`, including real check failure/correction,
scope and checker binding, source eligibility, exact recovery, account rejection,
allowance exhaustion, feedback failure and bounded account history. This is not a
full repository test-suite claim. Native grammar and full-route qualifications are
recorded separately. Researcher-scripted responses are explicitly not model behavior.

Preparation errors remain visible. `checker-001` exposed that an already imported
installed urllib.parse could bypass the saved library; the checker now explicitly
imports and verifies the candidate module. An initial upstream discovery command
also attempted to import unused support as a top-level package; the corrected
specific module invocation passes all 72 original tests without changing source.
The first saved-state screen looked for GPU monitoring in its per-case output
instead of the owned runtime's parent output; the helper now uses the actual
monitor. The first full-route preparation incorrectly treated its growing console
log as a source file; the input source inventory now names the intended text files.
These are preserved offline preparation failures, not Qwen failures or retries.

The fresh URL task holds implementation fixed and independently checks meaningful
new tests and executable documentation. Qwen starts with no selected sources and
no working account. A separate design consultation uses the old configparser
evidence, not the fresh task or its researcher-written answer. The chosen system
is an account-plus-verification configuration; one live attempt cannot isolate
the causal contribution of either component or establish pressure continuity.
