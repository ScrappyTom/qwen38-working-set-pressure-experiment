# Experiment 020 Specification

## Question

Can the earned signal-bearing event-frame controller complete fresh, real
owner-controlled audit/repair tasks whose correct task-compliant path must
cross an authentic 25,000-token pressure boundary before the first mutation?

Experiment 019 is immutable infrastructure-stop evidence. Experiment 020 is a
fresh sibling bank, not a retry or repaired reclassification of its exposed
task.

## Conditions

- `R50`: the unified signal-bearing event plane remains resident with all exact
  action/result bodies under the physical 50,176-token slot.
- `X25`: the same event plane retains readable type/target/status/bindings while
  the oldest exact payload bodies move to external custody after pressure.

Before pressure, paired conditions receive byte-identical requests and actor
behavior. X25 additionally preserves a prospective 1,000-token total operating
reserve inside the 25k hard envelope by externalizing more of the oldest exact
payloads when necessary. This is a mechanical capacity rule: it does not rank,
summarize, select, or inject information.

Both conditions use the same:

- exact authorized task and current candidate;
- hierarchical readable P0;
- canonical payload identities and explicit reopen actions;
- deterministic maximal exact whole-line reads;
- 512-token server-capped private reasoning;
- strict candidate/file/check bindings;
- 24-action budget, sampler, actor, tools, and schedule.

## Offline admission gates

The model-free ideal path is executed through the actual candidate, read,
patch, checker, event-frame, externalization, tokenizer, and submission code.
For both tasks and both conditions, qualification must establish:

1. the paired prefix is identical;
2. the 25k request is denied while the same request remains physically
   admissible under R50;
3. no accepted patch occurred before that boundary;
4. every required file was read from line 1 through exact EOF before mutation;
5. the exact donor successor is reached;
6. public and hidden checks pass;
7. submission occurs;
8. at least four action opportunities remain when the first check is offered;
9. every admitted ideal request retains at least 1,000 total tokens of
   headroom after runtime and output allowances.

The injected candidates must fail both public and hidden checks. Evaluator
bytes remain absent from the execution package.

## Prospective execution

- two tasks × two seeds × paired R50/X25 branches = eight branches;
- one attempt per branch;
- zero retries, repairs, rescues, or cross-cell history;
- exact frozen ordinal schedule;
- response seal before evaluator access;
- no automatic successor.

An early submission that omits the required pre-mutation inspection is a task
noncompliance even if its candidate happens to pass a checker. Host/integrity
failures stop the remaining schedule. Model-quality failures remain observed
outcomes and do not receive rescue.

Every saved prompt, private reasoning record, final action, exact result,
candidate, check, and host decision must be read directly before diagnosis.
