**Bug 1: `_safe_relative_path` - path safety**
Current code:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The issue: The condition `path.is_absolute() and ".." in path.parts or not path.parts` is parsed as `(path.is_absolute() and ".." in path.parts) or (not path.parts)` due to operator precedence. This means:
- Absolute paths WITHOUT `..` parts are NOT rejected (e.g., `/etc/passwd` would pass through)
- Paths with `..` but that aren't absolute ARE not rejected (e.g., `../foo`)

The fix should reject:
- Absolute paths (any path starting with `/`)
- Parent traversal (`..` in any part)
- Empty paths (no parts)
