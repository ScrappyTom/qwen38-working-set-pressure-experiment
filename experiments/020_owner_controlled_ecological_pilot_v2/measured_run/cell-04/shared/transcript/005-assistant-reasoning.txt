     ```python
     def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
         normalized = path_or_name.replace("\\", "/")
         path = PurePosixPath(normalized)
         if path.is_absolute() and ".." in path.parts or not path.parts:
             return None
         return path
     ```
     The bug here is operator precedence. The condition `path.is_absolute() and ".." in path.parts or not path.parts` is evaluated as `(path.is_absolute() and ".." in path.parts) or (not path.parts)`. This means:
     - An absolute path WITHOUT ".." would NOT be rejected (because the first part is False, and `not path.parts` is also False for non-empty paths)
     - A relative path WITH ".." would NOT be rejected
     - The correct logic should be: reject if absolute OR has "..
