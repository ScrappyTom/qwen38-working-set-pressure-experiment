3. Now I need to fix the path rejection issue. Looking at the current `_safe_relative_path` function:

```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The bug here is operator precedence. The condition `path.is_absolute() and ".." in path.parts or not path.parts` is parsed as `(path.is_absolute() and ".." in path.parts) or (not path.parts)` due to Python's operator precedence (`and` binds tighter than `or`).

This means:
- An absolute path WITHOUT `..` in its parts would NOT be rejected (because `path.is_absolute() and ".." in path.parts` is False, and `not path.parts` is also False for an absolute path)
- A relative path WITH `..` would NOT be rejected (because `path.is_absolute()` is False, so the first part of `and` is False, making the whole `and` expression False, and `not path.parts` is False)

The correct logic should reject:
- Absolute paths (regardless of whether they contain `..`)
- Paths containing `..` (parent traversal)
- Empty paths

So the fix should be:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if not path.parts or path.is_absolute() or ".." in path.parts:
        return None
    return path
