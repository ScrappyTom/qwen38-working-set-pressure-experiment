**Bug 1: `_safe_relative_path` doesn't properly reject absolute paths and parent traversal.**

Current code:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The issue is operator precedence. The condition `path.is_absolute() and ".." in path.parts or not path.parts` is evaluated as `(path.is_absolute() and ".." in path.parts) or (not path.parts)`. 

So it only rejects if the path is BOTH absolute AND contains `..`, OR if the path has no parts (empty). But:
- An absolute path WITHOUT `..` like `/etc/passwd` would NOT be rejected
- A relative path with `..` like `../foo` would NOT be rejected
- Empty string would result in `PurePosixPath("")` which has empty parts, so that's caught

The fix should be: reject if the path is absolute OR contains `..` in its parts OR has no parts.

```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if not path.parts or path.is_absolute() or ".." in path.parts:
        return None
    return path
```
