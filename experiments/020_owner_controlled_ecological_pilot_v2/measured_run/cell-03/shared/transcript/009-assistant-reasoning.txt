Looking at the current `_bounded_timeout` function in verifiers.py:
```python
def _bounded_timeout(value) -> int:
    try:
        timeout = int(value)
    except (TypeError, ValueError):
        timeout = 20
    return max(1, max(timeout, MAX_COMMAND_TIMEOUT_SECONDS))
```

This has a bug: `max(1, max(timeout, MAX_COMMAND_TIMEOUT_SECONDS))` means it always returns at least 60. The correct behavior should be to clamp to the inclusive range 1..60, so it should be `min(max(timeout, 1), MAX_COMMAND_TIMEOUT_SECONDS)` which is `min(max(timeout, 1), 60)`.

For `_safe_relative_path`, looking at the current code:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The issue is the condition `path.is_absolute() and ".." in path.parts or not path.parts`. Due to operator precedence, this is `(path.is_absolute() and ".." in path.parts) or (not path.parts)`. So it only rejects absolute paths that ALSO contain "..", but doesn't reject:
- Absolute paths without ".." (e.g., "/etc/passwd")
- Parent traversal without absolute path (e.g., "../foo")

The fix should be: reject if the path is absolute, OR if it contains ".." in its parts, OR if it has no parts.
