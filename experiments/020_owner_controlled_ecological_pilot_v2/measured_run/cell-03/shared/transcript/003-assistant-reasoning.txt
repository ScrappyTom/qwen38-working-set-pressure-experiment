1. **Path safety** (`_safe_relative_path`): The current logic is:
```python
def _safe_relative_path(path_or_name: str) -> PurePosixPath | None:
    normalized = path_or_name.replace("\\", "/")
    path = PurePosixPath(normalized)
    if path.is_absolute() and ".." in path.parts or not path.parts:
        return None
    return path
```

The condition `path.is_absolute() and ".." in path.parts or not path.parts` has a logic bug. Due to operator precedence, this is `(path.is_absolute() and ".." in path.parts) or (not path.parts)`. So it rejects absolute paths with `..` and empty paths, but does NOT reject:
- Absolute paths without `..` (e.g., `/etc/passwd`)
- Relative paths with `..` that could escape (e.g., `../../etc/passwd`)

The fix should reject:
- Absolute paths (any absolute path)
- Paths containing `..` (parent traversal)
- Empty paths

So the condition should be: `if not path.parts or path.is_absolute() or ".." in path.parts: return None`
