# Experiment 002: Single-Boundary Exact Reconstruction

**Status:** prospectively authorized by the owner's instruction, “Let's plan it
and test it,” following completion of Experiment 001F. Authority covers the
complete narrow study—implementation, offline qualification, development-only
live rehearsal, fresh-bank sealing, one exact measured execution, complete
transcript audit, results, commit, and push—subject to every fail-closed gate
below. It authorizes no retry, repair, rescue, semantic summary, automatic
successor, or recurrent-boundary study.

## 1. Earned question

P0 readable paths, symbols, signatures, and line ranges repeatedly improved
source localization. Richer resident relationships and exact evidence did not
earn promotion. No prior study crossed an authentic context-pressure boundary.

This experiment asks:

> Can the same reasoning-off Qwen actor continue correctly from a fresh active
> context of at most 25,000 tokens by using P0 and exact external custody to
> reacquire needed source or historical observations, compared with an
> append-only continuation of the identical pre-fork trajectory under 50k?

## 2. Conditions

```text
C50  exact pre-fork chronology remains append-only;
     request ceiling 47,000 tokens so the common 2,500-token output allowance
     fits inside the 50,176-token physical slot

T25  fresh reconstructed context;
     request + 2,500-token output allowance must fit within 25,000 tokens;
     exact external custody remains available through ordinary source tools
     and exact observation reopening

A25  mechanical capacity reference only;
     the unmodified pre-fork chronology is presented to the 25k guard and must
     stop before HTTP
```

C50 and T25 receive the same actor, task, current candidate, tools, P0
projection, pending phase, output allowance, sampler, and branch seed. The only
treatment difference is active chronology.

## 3. Exact fork

For each family and seed, Qwen produces one shared prefix trajectory. A fork is
eligible only when:

- the shared candidate has passed the frozen pre-fork check;
- the actor has accepted `fork_ready` under the common protocol;
- the exact prospective append-only continuation request plus 2,500 output
  tokens exceeds 25,000 tokens;
- that request plus output remains below the 50,176 physical context;
- the prefix and all exact artifacts replay;
- no evaluator truth has been read.

Both continuations bind the SHA-256 of the exact task, candidate snapshot,
record chain, observation inventory, P0 projection, and pending work. No
independently regenerated “equivalent” prefix may substitute.

## 4. T25 reconstructed context

T25 receives only mechanically justified continuity:

- the exact original task and constraints;
- exact current candidate identity;
- exact current stage and remaining invocation budget;
- the current ordinary tool contract;
- a current task-independent P0 path/symbol/signature/line-range projection;
- the exact latest `fork_ready` action/result;
- a complete bounded directory of externally custodied prior observations;
- explicit notice that older chronology is absent and exact information must
  be reacquired before reliance.

It receives no model-authored summary, retained-relevant set, host-selected
file, relationship inventory, semantic digest, repair hint, or evaluator truth.

The observation directory contains sequence, action type, readable target
identity, candidate binding, exact byte size, and an exact reopen handle. It
does not contain the observation body or a semantic preview. The actor may call
`reopen_observation(handle)` to obtain exact immutable result bytes. Current
source is reacquired through ordinary P0-guided tree/search/read operations.

## 5. Common tools

Both branches receive strict one-action JSON forms for:

- `tree`, `search`, and exact bounded `read`;
- exact candidate/file-bound `patch`;
- `check` with neutral IDs `prefork` and `public` as stage permits;
- `reopen_observation` over exact common-prefix result custody;
- `fork_ready` in the prefix only;
- terminal `submit` after the fork.

Every accepted action/result pair is exact, bounded, candidate-aware where
applicable, and enters the branch chronology. No tool performs semantic
ranking or relevance selection.

## 6. Fresh task geometries

The measured bank contains two fresh sibling families, never shown in the
development rehearsal:

1. **Source reacquisition.** A final cross-file repair depends on a governing
   source contract acquired early in the shared prefix and still available in
   the current candidate. T25 must use P0 and ordinary read to reacquire it.
2. **Observation reacquisition.** A final repair depends on an exact runtime
   compatibility observation acquired early in the shared prefix and absent
   from source. T25 must find and reopen that exact observation.

Each prefix performs real task-related inspection and a pre-fork candidate
change/check. Pressure bytes come only from exact task, source, actor, action,
result, and check chronology—never filler, duplicated padding, or hidden data.

The development fixture uses the same state-machine geometry but different
paths, symbols, values, source bytes, and evaluator truth.

## 8. Measures

Quality is primary:

- hidden correctness, submission, and exact-known-good identity;
- preservation of every governing constraint;
- C50/T25 matched outcome from each exact fork;
- A25 fail-closed capacity stop;
- exact fact reacquired before mutation;
- source versus observation reacquisition route;
- first-critical-information latency after fork;
- redundant reads and reacquisition churn;
- candidate, action, check, and observation binding;
- calls, prompt/completion tokens, endpoint time, maximum occupancy, and
  headroom;
- terminal reason and unused budget.

The direct audit must inspect every prefix and both continuations, including
the exact last pre-fork observation and every model-visible byte after reset.

## 9. Prospective decision

Single-boundary reconstruction is retained for a recurrent-boundary study only
if all hold:

1. at least three of four C50 branches pass, so the continuation task is
   viable under the larger control;
2. T25 hidden success is not lower than C50 and no C50-correct matched fork
   regresses;
3. both source-family T25 branches reacquire the governing exact source before
   mutation;
4. both observation-family T25 branches reopen the governing exact observation
   before mutation;
5. every T25 request plus output allowance stays within 25,000 tokens and every
   A25 reference stops before HTTP;
6. no host-selected relevance, hidden omission, stale current-source claim,
   cross-branch feedback, retry, repair, or rescue occurs.

If T25 remains correct but uses more calls or tokens, record the overhead; that
does not defeat the capability claim. If it fails to reacquire source, study
information policy before adding richer retrieval. If it cannot recover the
historical observation through the exact directory/reopen mechanism, that is
direct evidence about temporal continuity. No result automatically authorizes
recurrent boundaries or semantic digestion.
