# Experiment 002 implementation plan

## Objective

Build the smallest auditable harness that creates one authentic shared
near-25k coding chronology and compares exact append-only continuation with
fresh-context exact reacquisition.

## Sequence

1. Implement strict JSON/hash helpers, immutable candidates, safe paths,
   bounded ordinary tools, isolated checks, and exact artifact/record custody.
2. Implement task-independent P0 extraction using readable paths, top-level
   symbols, signatures, and exact line ranges only.
3. Implement exact observation custody, complete readable observation
   directory generation, and `reopen_observation` without summaries.
4. Implement the staged common-prefix runner, eligibility guard, exact fork
   receipt, C50 append-only request, T25 reconstruction request, and A25
   capacity-stop proof.
5. Construct one development family and prove scripted reachability, branch
   identity, replay, grader discrimination, paging, empty-file semantics, and
   capacity behavior.
6. Qualify the exact multi-turn state machine on the real endpoint using
   development material only. Directly inspect every rehearsal input/output.
7. Construct two fresh measured families, freeze evaluator separation,
   schedule, first requests, execution-only files, full source closure, actor,
   runtime, and authorization.
8. Execute four shared prefixes and eight continuations once, seal responses,
   shut down, and replay before evaluator access.
9. Hidden-grade and directly audit every prefix/branch. Publish paired results,
   update governance/status, commit, and push.

## Fail-closed conditions

Stop before measured calls if the exact fork differs between branches, pressure
uses filler rather than task chronology, any T25 request can exceed 25k,
observation indexing is incomplete, evaluator bytes enter execution, a check
does not discriminate, a scripted branch cannot reach known-good, replay or
clean-clone reconstruction differs, or the rehearsal exposes a new execution
defect.

During measured execution, ordinary model-quality failure is preserved and the
schedule continues. Transport, integrity, capacity, closure, or server-identity
failure stops remaining calls.
