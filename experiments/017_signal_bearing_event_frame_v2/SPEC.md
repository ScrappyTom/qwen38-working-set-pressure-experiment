# Experiment 017: Signal-Bearing Event Frame V2

## Purpose

Correct the exact capacity defect found by Experiment 016 without repeating
the earlier metadata mistake of treating an opaque identity as useful model
information.

An event handle is only an address. The resident frame must itself retain
mechanically grounded signal sufficient to understand progress:

- action type and readable target;
- exact predecessor candidate/file bindings;
- acceptance or rejection;
- exact successor, check, file, range, continuation, and terminal bindings;
- which bulky exact fields are externally available.

Only patch `old`/`new` payloads and exact result-body fields move behind exact
handles. No summary, task-aware label, ranking, semantic relation, or host
sufficiency judgment is added.

## Offline gates

Using the exact Experiment 016 sixteen-event stress sequences, V2 must admit:

1. all sixteen old event payloads external under X25;
2. fifteen old events external plus one maximum newly resident event under
   X25;
3. byte-identical R50/X25 requests before any externalization;
4. exact `reopen_event(EVT-nnnn)` recovery of the custodied `old`/`new`
   payload with size/hash verification;
5. exact resident pair reconstruction and monotonic sequencing.

R50 may still reach authentic physical pressure with all bodies resident; its
guard must fail closed.

## Exposed development qualification

Run six sacrificial branches against the frozen AD-IQ2_S actor:

- the two exposed Experiment 015 closure/stale-check donors under both seeds;
- one new development-only historical-action case under both seeds.

The donor cases test whether compact resident signal still supports check and
closure after `old`/`new` and result bodies leave context. The historical case
removes a marker from current source before the branch starts. The event's
resident fields identify the accepted patch target and candidate transition,
but do not reveal the marker. The actor must use that signal to select
`reopen_event`, recover the exact old payload, mutate the current candidate,
check, and submit.

## Execution rules

- one attempt per branch;
- zero retry, repair, or rescue;
- fresh context per branch;
- six calls maximum per branch;
- exact request/response/reasoning/action/result custody;
- response seal before hidden grading;
- direct review of every saved model input and output;
- no fresh large-world fixture or measured claim.

The run may establish only development comprehension and access-path fitness.
It cannot establish large-world behavioral value.
