## Prelaunch and post-run custody notes

An attached client process disappeared during immutable preflight before the
runner created its output root. No server, port listener, request, or model
artifact existed. A subsequent background-launch command was rejected by
Windows before process creation because its requested log path was not
writable. Neither event crossed the execution boundary. The single run that
created the evidence root is the run reported above.

During post-run analysis, the first verifier version mistakenly called the
seal-construction helper and rewrote only the repository copy of
`RESPONSE_SEAL.json` to include the post-seal grader. The receipt/hash mismatch
immediately exposed the mistake. The immutable external tree was untouched;
the copied seal was restored byte-for-byte, all 805 copied files were compared
to the external source, and the verifier was changed to read-only validation.
This analysis-path defect did not affect requests, responses, candidates,
grading, or the original response seal.

## Validity boundary

The live cases were exposed development material. They can establish:

- actor comprehension of V2's placement;
- exact event-payload access-path fitness;
- closure and current-check behavior with bulky bodies absent;
- bounded recovery from one stale binding.

They cannot establish large-world utility, a population success rate, or an
R50/X25 treatment effect. A future comparison must use fresh fixtures.
